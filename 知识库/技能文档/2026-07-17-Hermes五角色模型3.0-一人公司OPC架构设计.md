## 概述

小屿AI分享的 Hermes Agent Team 五角色模型 v3.0，从 v2.0 的四角色升级到五角色，引入了独立质量审计机制。核心是为一人工司（OPC）模式设计一套完整的 Agent 团队分工架构，解决原生 Hermes 的幻觉、记忆污染和角色混乱问题。视频时长 14:05，发布于 2026-07-17。

## 核心问题

单个 Agent 存在三大缺陷：

- **幻觉** — Agent 生成未经验证的内容
- **记忆污染** — 不同任务的上下文互相干扰
- **角色混乱** — 同一个 Agent 在不同任务间切换身份不清

多 Agent 系统需要明确的分工和边界。

## 四概念区分

| 概念 | 说明 |
|------|------|
| Profile（角色） | 定义 Agent 身份、职责、行为边界 |
| Project（项目） | 具体的工作目标和任务 |
| Wiki（知识库） | 共享记忆层、项目管理层、架构规范层 |
| Session（会话） | Agent 与人类的交互过程 |

## 五角色模型

### 1. Coordinator（协调者）
- 总体统筹、任务分发、进度跟踪
- 信息路由的枢纽

### 2. 编排者
- 任务拆解、工作流设计、步骤编排
- 负责从需求到可执行路径的转换

### 3. Researcher（研究员）
- 信息检索、资料收集、事实核查
- 负责未验证材料采集

### 4. Writer（写作者）
- 内容生成、文档撰写、代码编写
- 负责正式产出

### 5. Editor（编辑者） ← **v3.0 新增**
- **独立质量审计角色**
- 审核 Researcher 和 Writer 的产出
- 不通过则打回修正
- "管流程的不能管质量" —— 审计与执行分离

## 角色 Profile 结构

每个角色有一套 6 层文件结构，核心是 L1 的 `soul.md`：

- **L1 - soul.md** — 角色的灵魂定义（身份、价值观、行为准则）
- **L2-L6** — 逐层细化（工具、知识、约束、权限等）

"换角色需换 profile"——切换角色时切换整套 profile 文件。

## Wiki 的三层角色

在五角色模型中，Wiki 承担三个职能：

1. **共享知识库** — 团队级公共知识，所有角色可读取
2. **项目管理** — 长期任务的规划、进度、决策记录
3. **架构规范** — 代码规范、设计规则、接口约定

## 信息路由规则

**每类信息只有唯一存放位置。** 避免信息错放：

- 角色定义 → profile 文件
- 项目进度 → 项目空间
- 知识积累 → wiki
- 会话记录 → session

## 质量保障体系（三层递进）

| 层级 | 机制 | 说明 |
|------|------|------|
| 第一层 | Session Gate | 会话级准入检查 |
| 第二层 | 三级置信度 | 对产出进行置信度评级 |
| 第三层 | 独立核查 | Editor 角色独立审核 |

### 关键规则

- **未验证材料不进正式产出** — Researcher 采集的原始材料必须经过验证
- **角色产出不通过则打回修正** — Editor 有否决权
- **Human 在关键节点介入** — 人类在重要决策点审核
- **发布交付失败自动重试** — 技术层面保证可靠性
- **写入前校验** — 防止数据污染，检查污染预警信号

## 项目空间模式

每个长期任务都应有自己的项目空间。同一套 profile 团队可以服务多个 project——角色配置与项目数据分离。

## 战略分析

**与用户实践的直接关联：**

这个视频直接触及用户当前使用的 Hermes Agent 体系。五角色模型是针对原生 Hermes 缺少角色分工设计的补丁方案，其核心理念与用户的"幕僚长"角色设定高度共鸣——不同的 Agent 应该有明确的身份边界和职责。

**值得借鉴的设计：**

1. **审计与执行分离** — Editor 独立于其他四角色是最重要的设计决策。用户当前的"幕僚长"角色本身就是审计者，但五角色模型把审计机制体系化了（session gate → 三级置信度 → 独立核查）。

2. **profile 与 project 分离** — 同一套角色文件可服务多个项目。这对应 Hermes 的 skills/ 目录（skill 可跨项目复用），但五角色模型给出了更结构化的文件层级（6 层 profile 结构 + soul.md 为核心）。

3. **信息路由规则** — "每类信息只有唯一存放位置"是用户 wiki（README.md + 快速导航.md + 索引目录/）的强化版。五角色模型把这个原则延伸到了 Agent 的 memory 管理。

**差距与局限性：**

1. 视频是教程/产品推广性质（评论区索取"五角色模型"文件），不是开源方案。具体文件结构未完全公开。
2. 五角色模型的实践细节（6 层文件结构的具体内容、coordinator 的工作流定义）需要获取实际模板文件才能评估深度。
3. 模型聚焦于一人公司（OPC）场景，团队规模越大，该模型的扁平角色划分可能不够。

**整合可能性：高。** 五角色模型与用户当前的"幕僚长"运营模式同属一个范式。关键整合点：
- soul.md 的概念可以作为 Hermes skill 的前置定义层
- Editor 独立审计机制可以整合到用户的工作流（在提交给主理人之前，Editor 角色先做质量检查）
- 三级置信度评级可以整合到 Hermes 的产出验证流程中
