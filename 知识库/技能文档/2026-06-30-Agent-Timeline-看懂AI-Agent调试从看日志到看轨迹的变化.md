# Agent Timeline：看懂 AI Agent 调试从"看日志"到"看轨迹"的变化

> 来源：微信公众号「一览清风」
> 日期：2026-06-30
> 原文：[微信链接](https://mp.weixin.qq.com/s/wbSt7I1kk428JfMrJhMECQ)

---

## 核心概念

> **Agent Timeline 是一次 AI Agent 运行的"时间轴病历"：把用户请求、模型调用、工具调用、数据库访问、错误、重试、人工审批和最终结果，按时间顺序串成一条可复盘轨迹。**

三个关键词：
1. **一次运行** — 不是统计平均，而是某一次任务到底发生了什么
2. **时间顺序** — Agent 的错误常常来自顺序（先查旧文档→再生成错误回答）
3. **可复盘轨迹** — 让人能沿一条线看清楚每一步

---

## 为什么需要 Agent Timeline：六类失败点

Agent 系统至少有六类失败点，不再是传统的"模型输出"一个点：

| 失败类型 | 典型问题 |
|---------|---------|
| **输入失败** | 用户任务含糊、矛盾、缺少上下文 |
| **模型失败** | 误判意图、错误计划、模型版本变化 |
| **工具失败** | API 500、超时、参数错误、权限不足 |
| **数据失败** | 检索引旧政策、SQL 漏条件、文档解析丢失 |
| **控制失败** | 高金额退款未转人工、删除未确认、外部邮件未审核 |
| **结果失败** | 客服差评、测试失败、工单重开、代码被退回 |

**没有轨迹时，团队把所有问题都归咎于模型；有轨迹时，团队才知道该修哪里。**

## Agent Timeline vs 传统做法

| 维度 | 过去：看回答/看日志 | 现在：看 Agent Timeline |
|------|-------------------|----------------------|
| 关注对象 | 最终输出或单点日志 | 一次任务的完整链路 |
| 常见问题 | 不知道错误发生在哪一步 | 能定位模型/工具/数据/权限/下游系统 |
| 数据组织 | 分散在模型平台、应用日志里 | 用 conversation id / trace id 串起来 |
| 调试方式 | 猜提示词、换模型、人工复现 | 沿时间轴查看 span、错误、重试 |
| 风险治理 | 事后看结果 | 事中记录证据，事后可审计 |

**关键变化：调试单位从"模型回答"变成"一次任务链路"。**

## 为什么 OpenTelemetry 很关键

Honeycomb 选择 OpenTelemetry GenAI 语义约定作为基础。标准化的字段命名（模型请求/响应、Token 用量、工具调用、Agent 名称、conversation id）让：
- 换模型后历史数据可对比
- 换框架后监控面板不用重做
- 成本、延迟、质量放在同一张表分析
- 合规审计有证据链

**Agent 的轨迹不应该停在模型边界** — 下游 HTTP 请求、数据库查询、队列任务也应该带上同一个 conversation id。

---

## 落地实践：6 步建立最小可用轨迹

1. **选一个真实任务链路** — 客服退款、代码缺陷修复、数据分析报告等
2. **每次运行分配 ID** — conversation id / trace id 贯穿整条链路
3. **记录模型和提示词版本** — 请求模型名、响应版本、prompt 版本、token 用量、延迟、finish reason
4. **记录工具调用** — 工具名、参数、结果摘要、错误类型、重试次数、耗时、是否降级（**敏感字段脱敏**）
5. **记录下游系统** — 数据库、HTTP API、队列的下游 span 要串起来
6. **把质量反馈接回来** — 用户满意度、人工审核结果、测试结果、代码 review 状态

---

## 边界与风险

1. **数据集** — 不要把所有 prompt 和工具返回原样记录到长期存储；生产环境考虑脱敏、保留时长、访问权限
2. **看到轨迹 ≠ 理解业务正确性** — 需要和评测、人工审核、业务指标结合
3. **采样和成本控制** — 高风险全量、普通按比例、失败提高采样
4. **标准仍在演进** — 短期内采用核心字段（conversation id、agent name、model、token、tool、error、latency）

---

## 对个人的启示

- 保存 3-5 个真实任务样本
- 记录 AI 用了哪些资料和工具
- 要求 AI 输出"不确定点"和"验证步骤"
- 失败时不要只换模型，复盘哪一步出错

> **AI 的结果要能被追溯。**
