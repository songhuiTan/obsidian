# Claude Code官方Loop Engineering教程：基于Fable 5的实践示例

## 0. Loop官方定义

**Agent重复工作循环，直到满足停止条件。**

四种Loop按**触发方式**和**停止条件**分类：

| 类型 | 你交出去的是什么 | 人工参与度 |
|------|-----------------|-----------|
| **Turn-based** | 验证环节 | 高 |
| **Goal-based** | 验证环节 + 停止条件 | 中 |
| **Time-based** | 验证环节 + 停止条件 + 触发时机 | 低 |
| **Proactive** | 全部（连 prompt 都不用发） | 极低 |

每往上一级，人工手里就少一件事。

---

## 1. Turn-based：把人工验收写成 skill

基本模式：人工发 prompt → Claude 干活 → 人工 check → 继续下一轮。

**要交出去的是「你检查」这个环节。**做法是把人工验收的动作写成 skill（操作规范写成文档喂给 Claude）。

### 案例：纯静态待办清单页面 + verify-ui-change skill

skill 核心五条：
1. 启动本地服务，用浏览器工具打开页面
2. 真实操作改动的控件，截图 before/after 对比
3. 涉及持久化的改动，刷新页面确认状态保留
4. 浏览器 console 零新增报错
5. 任何一步失败，修复后从第1步重来，不交半成品

**A/B 测试方法：** 先禁用 skill，让 Claude 给页面加暗色模式切换按钮→人工 reviewer 数来回几轮、抓问题。重置代码、恢复 skill，同一条 prompt 再来一遍→看它会不会自己启动服务、亲手点按钮、刷新验证、查 console。

> 关键原则：**检查越量化，Claude 自验证越容易。**

## 2. Goal-based：用 /goal 决定什么时候停

`/goal` 背后挂了个评估模型，相当于用另一个模型当裁判。每次 Claude 想收工，裁判对照你写的条件查一遍，不达标打回去继续，直到目标达成或轮数用完。

**完成标准必须可量化：** 测试通过数、分数阈值等。

### 案例：日期解析器（12个 pytest 用例，埋3个 bug）

Goal prompt 示例：
```
/goal python3 -m pytest的12个用例全部通过。
只允许修改dateparse.py，不允许改动任何测试文件。
最多尝试5轮。
```

两条限制比目标本身还重要：
- **不允许改测试** → 少了这条，通过测试的最短路径是把测试改到能过，是 goal-based loop 最常见的越界姿势
- **最多5轮** → 成本限制，/goal 会一直打回重试，不设上限 token 消耗顶不住

---

## 3. Time-based：用 /loop 监控会变化的事情

有些工作的状态不归你控制：CI 过没过、reviewer 有没有留言、队列空没空、训练进程等。最简单的接法就是按间隔轮询，有变化就反应。

### 案例：PR 自动化修复

1. setup.sh 脚本：建私有仓库 → 推 CI 全绿的 main 分支 → 开一个必挂的 PR（percentile 函数带3处 lint 错误 + 1个算法 bug）
2. 启动：

```
/loop 每5分钟检查PR的CI状态：
如果失败，读取失败日志，修复问题并push；
有未处理的review评论就逐条处理；
CI全绿且无未处理评论时停止。
```

**关键洞察：**
- 停止条件写不清，loop 就会一直转下去
- 循环间隔不要瞎设：CI 一轮跑两分钟，30秒查一次浪费 token

## 4. Proactive：人工退出实时环节

不是新的 Loop 类型，是前三者的组合：
- `/schedule` 管触发
- goal 式描述管单次运行何时算完
- 条条写死的权限边界

**人工可以不在现场，但上述三样都得事先写进 prompt。**

### 案例：用户反馈流水线

一个文本工具库埋了3个潜伏 bug，用户报告以 markdown 文件流入 inbox 目录。loop 任务：分诊每一份报告 → 修复 → 答复 → 改状态。

4份报告中3份是真 bug，1份不是（要求 word_count 支持中文分词——这是新需求，考分诊判断）。

Prompt 中划了两条边界：
- 只允许改 app 目录和报告文件
- 新需求一律不现场实现，写答复转需求

> 那份中文分词报告就是试金石：它要是热情地当场把功能写了，说明你的边界没写到位。

---

## 5. 比案例更重要的事

### 质量
某一轮结果不达标，别只修复那一次——**把修正编码回系统**，加进 skill、goal 描述或边界规则，让之后每一轮都受益。

### 成本（三个开关）
- `/usage`：看 token 在 skill 和 subagent 上消耗分布
- `/goal`：不带参数看当前已用轮数和 token
- `/workflows`：看每个 agent 的用量，随时叫停

### 模型路由建议
routine 批量活路由到更小更快的模型，最强模型留到关键决策和规划时使用。
