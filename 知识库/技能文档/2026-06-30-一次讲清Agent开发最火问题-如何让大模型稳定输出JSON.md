# 一次讲清Agent开发最火问题：如何让大模型稳定输出JSON

> 来源：微信公众号「从数学到智能体」
> 日期：2026-06-30
> 原文：[微信链接](https://mp.weixin.qq.com/s/F_nKFylvJiVVcNnQodLgoQ)

---

## 核心观点

解决 LLM 输出 JSON 不稳定的问题，不能迷信完美的提示词，而是要建立一套 **层层防护的工程防线**：

```
事前预防 → 事中纠错 → 事后自愈
```

---

## 一、为什么大模型输出 JSON 不稳定？

1. **自回归生成的局部最优** — 一次只吐一个 Token，中间随机性导致错误不可挽回
2. **指令理解的"偷懒"倾向** — 模型倾向于输出简短的编号而不是完整的 JSON 对象
3. **思维链（CoT）与格式约束的冲突** — 思考过程的结构化语言与 JSON 大括号混杂

---

## 二、三层防护体系

### ① 提示词防御（事前预防）

- **去噪与去歧义**：选项编号避免使用 `JSON 1:`、`JSON 2:` 等含 JSON 关键字的标签
- **XML 标签隔离**：要求模型把 JSON 输出在 `<result>...</result>` 标签中，用正则 `re.search(r'<result>(.*?)</result>', text, re.DOTALL)` 剥离
- **显式提供 Empty 模板与 Few-shot**：填空式示例，强化每个 Key 的存在感

### ② 容错解析与修复（事中纠错）

- **`json_repair` 库**：对截断、漏引号、尾部逗号等小毛病自动修复
- **特定语法规整**：值内未转义的双引号，自动替换为全角或加反斜杠

### ③ 自愈与控制回路（事后兜底）

- **温度微调重试**：失败后调整温度（0.3/0.5）重试，避免 0.0 复现同错误
- **序号回溯语义恢复**：检测到输出编号 `"选项4"`，代码层自动从候选列表取回对应 JSON
- **自我修正（Self-Correction）**：将报错信息 + 损坏的 JSON 喂回模型让自查自纠

---

## 三、策略选择矩阵

| 异常表征 | 针对性策略 |
|----------|------------|
| JSON 尾部被截断 | `json_repair` 补齐括号 |
| 返回文本夹杂废话 | XML 标签隔离 + 正则提取 |
| 值内双引号未转义 | 正则预处理 / 重试 |
| 模型只返回选项编号 | 提示词去噪 + 序号回溯兜底 |
| 完全是自然语言 | 温度微调重试 |

**选型建议：**
- **在线实时交互** → 提示词硬约束 + json_repair + 序号回溯 + 温度重试（解决 95%+）
- **后台批量任务** → 额外引入 Self-Correction 机制

---

## 四、终极防线：语法约束解码（Guided Decoding）

在模型 **输出的同时** 直接物理限制：

- 推理引擎（vLLM / SGLang / Llama.cpp）在每步 Token 预测时将不符合 JSON Schema 的 Token 概率强行置零（Logits Masking）
- **100% 绝对稳定**，完全消除应用层解析报错
- **代价**：依赖底座引擎的控制权（不支持透传 `guided_json` 的网关无法使用）；复杂 Schema 可能有微小首字时延

---

## 五、总结

> 技术落地，从来不是为了追求理论上的纯粹，而是在各种妥协与局限性中找到性价比最高的解法。

多层组合防线是 AI 工程落地的实在锚点。
