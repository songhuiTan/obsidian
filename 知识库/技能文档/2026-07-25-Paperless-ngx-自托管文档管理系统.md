## 概述

扫描仪把纸质合同变成 PDF，文件却还是叫 `scan_0032.pdf`。发票、保单和证明材料散在不同文件夹里，半年后想找一笔金额，只能逐个打开。

**Paperless-ngx**：自托管文档管理系统，面向家庭、个人工作室和小团队。会读取扫描件、邮件附件和电子文档，**识别正文、补充分类，再放进一个可搜索的档案库**。适合保存发票、合同、账单、保单和证明材料，**不适合当通用网盘**。

关键事实：
- 41.6k Stars，持续更新
- 网页端、数据库、任务队列和 OCR 分开运行，官方完整 Docker 部署文档
- **保留原始文件**，也能生成适合长期保存的 PDF/A
- 迁移时不必把资料锁在网页界面里
- 核心主张："它把'保存文件'往前推进一步：**资料多年后依然能被准确找到**"

## 三个能力

### 1. OCR 和全文搜索

- 识别 PDF 与图片里的文字，保存为可搜索内容
- 文件名再随意，也能按公司名称、金额、地址或合同条款查找
- 搜索叠加日期、联系人、文档类型和标签
- 资料多起来后，比依赖文件夹层级更稳定

### 2. 自动导入和分类

- 扫描仪、NAS 或手机同步工具把文件放进 `consume` 目录，系统自动读取
- 邮件里的账单和发票附件按规则进入档案库（少一次下载上传）
- 系统可**预测联系人、标签和文档类型**——前期要人工校对，资料格式越统一分类越准

### 3. 工作流和权限

- Workflow 根据文件名、正文、来源或字段触发动作：添加标签、修改类型、分配用户、生成存储路径
- 多人使用时限制不同用户可见/可修改的文档
- ⚠️ 规则写得太宽会造成批量误分类

## 用 AI Agent 安装

有 Codex、Claude Code 或 Gemini CLI 时直接执行 Prompt（要求 Docker Compose + PostgreSQL + Redis + 持久化数据库/媒体/consume/export 目录 + 不删现有 Docker 数据 + 检查容器状态和访问地址 + 报告备份目录）。

手动安装一行：

```bash
bash -c "$(curl --location --silent --show-error https://raw.githubusercontent.com/paperless-ngx/paperless-ngx/main/install-paperless-ngx.sh)"
```

## 优点和限制

**优势**：流程完整——导入、OCR、搜索、分类、工作流和权限在同一系统；Docker 文档清楚；对已有 NAS/家庭服务器的新增成本主要是存储、备份和日常更新。

**代价（自托管）**：
- 文档默认**明文保存**，不应部署在不可信主机上；公网访问需 HTTPS、强密码和访问限制
- **备份不能只复制 PDF**——数据库里保存 OCR 文本、标签、权限和工作流，数据库与媒体目录必须一起备份
- OCR 受扫描质量影响：倾斜照片、模糊文字、复杂表格、多语言混排都可能识别错误；**金额和日期需要人工检查**

## 写在最后

适合资料多到靠文件夹难以维护、但不需要完整企业审批系统的人。不会替你设计标签，也不保证每次 OCR 准确——前期花时间整理文档类型、联系人和规则，后面才能稳定省下查找归档时间。

> 当账单、合同和证明材料都能按正文和字段找到，硬盘里的 PDF 才算形成了可长期使用的档案库。

## 战略分析

**Paperless-ngx 是"个人/小团队文档知识管理"的成熟开源方案**，与知识库已有内容形成对照：

| 本文概念 | 知识库已有对应 |
|---------|--------------|
| OCR + 全文搜索 + 元数据 | 生产级企业知识库指南（文档清洗、元数据留存、生命周期） |
| 自动分类预测（联系人/标签/类型） | 知识管理、gbrain 自动知识图谱 |
| 保留原始文件 + PDF/A 长期保存 | kb-builder（内容与工具分离）、Obsidian 纯 Markdown 原则 |
| 数据库+媒体一起备份 | 文档生命周期管理、数据治理 |
| 竞品对比（Docspell/Mayan EDMS） | 同类工具横向对比习惯 |

**核心启发：**

1. **"保留原始文件 + 生成 PDF/A"是长期归档的正确姿势**——与用户 Obsidian 知识库"内容纯 Markdown 可迁移"的精神一致：不锁死在某个工具里。Paperless-ngx 管纸质/票据类文档，Obsidian 管知识类内容，正好互补。

2. **"备份不能只复制 PDF——数据库里还有 OCR 文本/标签/权限/工作流"**是重要提醒——对用户的 Obsidian + gbrain 体系同理：光备份 .md 文件不够，gbrain 的 PostgreSQL 索引、TencentDB 记忆都要纳入备份范围。

3. **"金额和日期需要人工检查"**呼应生产级知识库的"后置校验"——OCR 对关键数字不可信，高风险字段要人工/规则校验，不能全自动。

4. **AI Agent 安装 Prompt 是实用模式**——用 Codex/Claude Code 部署时给出明确要求（不删现有数据、检查容器、报告备份目录），与知识库"Agent 指令模板"实践一致。

5. **对用户的价值**：如果用户有大量发票/合同/票据需要长期管理（个人财务、InStreet 平台相关），Paperless-ngx 是现成方案；它的"consume 目录自动导入 + 邮件归档"与用户的自动化工作流契合。

**一句话**：Paperless-ngx = 家庭/小团队的自托管文档归档系统（41.6k Star），OCR 全文搜索 + 自动分类 + 工作流权限，保留原件可迁移；"资料多年后依然能被准确找到"是其核心价值，备份必须数据库+媒体一起。
