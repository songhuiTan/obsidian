## 视频概述

Hermes 多角色架构 OPC 模式，专为"一人公司"设计的 Hermes Agent Team。通过多角色协作解决了单一 agent 的四大问题：幻觉、记忆污染、角色混乱、质量不可信。多 Agent 交叉验证确保视角完整性，防止单一视角"写嗨"，质量保障体系兜底。

## 核心问题：单一 Agent 的三大缺陷

1. **研究时下结论** — 研究阶段就急于得出结论
2. **写作时补研究** — 写作过程中临时补研究论证
3. **实现时自我辩护** — 对自己的输出缺乏批判视角

**根源：缺乏外部视角。**

## 架构：四个角色 + 共享 Wiki

| 角色 | 职责 |
|------|------|
| **协调者 (Coordinator/Orchestrator)** | 负责整体编排和任务分配 |
| **研究员 (Researcher)** | 负责信息搜集和研究 |
| **写作者 (Writer)** | 负责内容产出 |
| **构建者 (Builder)** | 负责实现和构建 |

协作方式：通过**共享 wiki** 进行协作，profile 定义角色身份，wiki 承载共享知识。

## 标准工作流

1. **确认项目目标** — 明确要做什么
2. **任务拆解** — 把目标拆成可执行任务
3. **角色执行** — 各角色按职责执行
4. **置信度审核** — 对输出进行置信度分级
5. **质检回查** — 交叉验证确保质量
6. **产出归档** — 每个文件有且仅有一个存放位置，避免污染
7. **复盘记录** — 沉淀经验和教训

## 质量保障体系

- **确定项目目标** — 防止目标漂移
- **置信度分级** — 对输出结果分级评估
- **Builder 自救流程** — 当构建遇到问题时自动启动排查
- **Writer 质检清单事项** — 写作者的质量检查清单

## 架构特性

- **多 Agent 交叉验证** — 确保视角完整性，防止单一视角写嗨
- **质量保障体系兜底** — 完善的审核机制
- **文件隔离** — 每个文件有且仅有一个存放位置，避免污染
- **跨项目复用** — 整个架构可跨项目复用，其余项目内容不会污染新项目
