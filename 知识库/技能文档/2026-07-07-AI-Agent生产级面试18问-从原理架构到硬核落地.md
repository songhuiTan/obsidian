# AI Agent 生产级面试 18 问：从原理、架构到硬核落地

> **来源**：银河技术 / Ray（微信公众号）
> **日期**：2026-07-07
> **原文链接**：https://mp.weixin.qq.com/s/4g8QeIETR2-0P6qWfVOKEQ

## 核心观点

生产级 Agent 的核心难点从来不是"让模型能说话"，而是让一个带推理能力、外部动作能力和状态依赖能力的系统，在高并发、可审计、可治理、可回放的前提下稳定运行。

## 参考架构：四层六面

**控制面**：模型路由、策略下发、版本灰度、预算控制、审批与风控
**执行面**：请求处理、规划、工具调用、工作流执行、输出
**状态面**：会话、记忆、任务状态、Checkpoint、事件日志、审计链路
**治理面**：可观测、评测、成本、限流、熔断、回放、补偿、上线规范

六层架构：接入层 → 编排层 → 工具层 → 模型层 → 状态层 → 治理层

## 18 问核心要点

### Q1：核心架构分层
单体 Agent Service 在 Demo 很快，生产里有四个问题：模型和工具耦合、状态和执行绑死、流式/异步/审计混在一起、每加工具就打补丁。**逻辑边界必须先拆清楚**，即使先放一个仓库也要模块化拉开。

### Q2：高并发有状态服务
**执行节点无状态化，会话状态外置。** 状态存储：L1 本地缓存 → L2 Redis Cluster → L3 PostgreSQL → L4 对象存储/OLAP。并发写用 CAS 版本写入而非全局锁。

### Q3：Plan-Execute-Observe 循环
建模成**显式状态机**而非隐式递归。每一步必须有明确输入输出、可中断可重试可观测、有终止条件、允许人工接管。终止边界：最大步骤数/墙钟时间/单步超时/Token 预算/连续失败/审批等待/安全拒绝。

### Q4：工具调用可靠性
防线：JSON Schema 校验 → 参数标准化 → 权限检查 → 幂等键生成 → 限流/Bulkhead → 超时/重试/熔断 → 执行 → 结果结构化 → 审计落盘。参数校验要有**自动修复**（数值化字符串、枚举别名、时间格式）。有副作用的工具**必须幂等键**。

### Q5：多 Agent 协作
**不要让多个 Agent 无边界对话。** 推荐 Coordinator + Worker 架构。所有跨 Agent 交互走显式事件，不走隐式共享内存。每个子任务有独立 ID、清晰状态、补偿策略。

### Q6：Memory 分层
三层：L1 短期对话记忆 → L2 工作记忆（当前任务中间事实） → L3 长期记忆（用户偏好/历史案例）。**记忆抽取比"记住全部"更重要。** 写入链路和模型回答链路分离。

### Q7：Checkpoint 与断点恢复
保存**最小恢复闭包**：任务状态、已完成步骤、下一步、预算、工作记忆摘要、幂等标识、外部等待点。三种写入策略：关键步骤前、外部副作用后、长任务按时间片。

### Q8：业务系统集成一致性
先区分只读/有副作用工具。推荐 **Outbox + 幂等消费 + 状态机** 模式。Agent 必须理解"发起成功"≠"业务完成"、"接口返回成功"≠"最终状态成功"。

### Q9：RAG
生产级 RAG 链路：Query Rewrite → Multi Retriever（dense+sparse+keyword） → Recall Merge → Rerank → Context Packing → Citation。必须加**来源约束**：可信度、过期、租户边界、引用追溯。

### Q10：模型路由与 Fallback
**LLM Gateway** 统一处理选择/限流/超时/熔断/降级/缓存/预算/审计。按任务复杂度 + 业务等级路由。Fallback 要考虑跨模型语义风格突变和 token 重新计费。

### Q11：缓存与成本控制
三层缓存：精确缓存 → 语义缓存 → 结果片段缓存。**Token 预算必须显式建模**（提示词/补全/成本/工具调用/时长）。

### Q12：流式响应
架构：Client → Gateway → Stream Hub → Agent Worker → LLM Gateway。Stream Hub 负责登记/分发/重连/ACK/心跳/背压。重连带 sessionId+taskId+lastAckSeq。

### Q13：安全隔离
四层防线：输入净化 → 策略决策（OPA） → 执行隔离（沙箱/网络白名单） → 输出过滤。**Agent 安全不是在防一个"坏模型"，而是在防"具有执行能力的不确定系统"。**

### Q14：可观测性
Trace（每个请求一个 Trace，每次模型/工具/检索/状态持久化一个 Span）+ Metric（QPS/成功率/P95/成本/超时率）+ Log（结构化，必带 traceId/tenantId/sessionId/taskId/stepId）。

### Q15：评测与 CI/CD
测试金字塔：单元测试 → 集成测试 → **回放测试** → 评测测试 → 灰度发布。回放记录：输入、初始状态、检索命中、模型请求/响应、工具参数/结果、最终输出、人工标注。

### Q16：异步化与长任务
任务状态机：CREATED→QUEUED→RUNNING→WAITING_APPROVAL→SUCCEEDED→FAILED→CANCELED。消费端：按 sessionId/taskType 分区、手动提交 Offset、退避重试、死信治理、业务键幂等。

### Q17：多租户与权限隔离
覆盖五层：身份层/数据层/检索层/工具层/观测层。Redis Key 和 SQL 查询都必须显式带租户条件。

### Q18：平台设计
Agent 平台 = **"带推理能力的工作流执行系统"**。六统一：接入协议/LLM Gateway/Tool Gateway/状态与 Checkpoint/评测与回放/预算与安全/多租户与审计。

## 上线前检查清单

- 架构：是否拆清了六层边界？是否有同步/异步两条路径？是否有断点续跑？
- 状态：会话外置？显式版本号？有副作用工具全部幂等？
- 安全：工具 ACL？高风险审批？检索带租户边界？输出脱敏？
- 稳定性：per-tool 限流/超时/熔断？模型 Fallback？队列重试/死信？流式重连/背压？
- 治理：全链路 Trace？按模型/工具/租户看指标？回放？灰度？预算告警？

## 面试中最容易答浅的 8 个点

1. 架构只讲 Prompt+Tool+Memory 三件套 → 应深入到状态机/幂等/Checkpoint
2. Memory 讲成"保留更多上下文" → 应讲分层+抽取+衰减
3. 工具可靠性讲成"失败就重试" → 应讲 Schema 校验+幂等+自动修复
4. 多 Agent 讲成"角色对话" → 应讲协调者+任务状态机+补偿
5. 流式讲成"WebSocket vs SSE" → 应讲 Stream Hub/重连/背压
6. 成本讲成"换便宜模型" → 应讲三层缓存+预算建模+降级策略
7. 安全只讲 Prompt Injection → 应讲四层防线+OPA+沙箱
8. 评测讲成"人工感觉更好" → 应讲回放+灰度+分层测试金字塔

## 总结

生产级 Agent 的本质不是更聪明，而是**更可控**：
- 能力边界拆清楚
- 状态当成一等公民
- 工具调用当成业务事务
- 模型当成不稳定外部依赖
- 治理做在设计里
