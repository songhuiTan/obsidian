# Archify：代码库 → 可交互架构图（东哥评测视角）

> **一句话**：一个 Agent Skill——把代码库丢给 AI，自动梳理运行时架构并生成**可交互 HTML 架构图**。可装到 Cursor、Claude Code、Codex CLI、OpenCode。东哥评测的核心关切：**图是不是瞎猜的，出了问题能不能回源码核对**——Archify 用 SRC 标记 + Git commit 绑定回答了这个问题。

## 项目信息

- **GitHub**：github.com/tt-a1i/archify
- **形态**：Agent Skill（非独立软件），装进 AI 编程工具后直接说"使用 archify 梳理这个仓库的运行时架构"
- **安装**：`npx skills add tt-a1i/archify -g`
- **临时试用**：`npx skills use tt-a1i/archify@archify --agent codex`

## 核心能力

- **输入**：一个代码库（陌生仓库/老项目/交接项目）
- **输出**：可交互 HTML 架构图——支持**架构图、Workflow、时序图、数据流、生命周期图**五种
- **交互**：HTML 内可搜索节点、看上下游、**查两个节点之间的调用路径**，开会可直接演示

## 东哥视角的三个关键判断

### 1. 图不是瞎猜的：SRC 标记可溯源
- 图里的节点带 **SRC 标记**，直接跳到对应**文件和行号**
- 位置还能**绑定具体 Git commit**——看到某个模块，点一下就能回代码核对，不用开 IDE 搜半天

### 2. 模型不负责硬画 SVG：JSON 出图 + 程序渲染
- **AI 只输出结构化 JSON**（整理节点、关系），布局和渲染交给程序，画完还有**自动检查**
- 老开发都懂：AI 直接写 Mermaid 或 SVG，改两次线就开始乱飞——JSON+程序渲染是质量不靠运气的关键设计

### 3. 别只信一张图：动态配置仍需人核对
- 陌生仓库再怎么自动分析，**入口、环境变量、数据库连接、异步 worker 这些地方仍要手动核对**
- 架构图省掉大量"翻目录"时间，但**动态配置、运行时分支**最好别只看图下结论
- 适用场景：接手老项目、技术交接、给新人讲系统

**2. 对 Hermes 的启发：**
- **"AI 出 JSON、程序渲染、自动检查"三分离**是可靠的生成式工具设计范式——AI 负责结构化事实（节点/关系），程序负责确定性输出（布局/渲染），检查器兜底。这与 J-Space"工具调用有诊断"、Yao"Output Eval Lab 输出断言"是同一哲学在不同层
- **可溯源设计（SRC 标记 + commit 绑定）**：任何 AI 生成的产出都应有"回到证据源"的路径——gbrain 的来源标注、归档文件的 source_url 都是同一原则
- 架构图类工具对用户的价值：研究陌生 repo（如刚 clone 的 TokBrain/Yao）时，"先出图再深读"是好路径；且 Archify 是 Agent Skill 形态，与 Hermes skill 体系同构

**3. 定位判断：** 轻量、即装即用、解决"接手陌生代码库"的高频痛点——比 AgentDesk/Yao 那种重型治理系统实用得多。适合作为 Hermes 生态的补充 skill（如果用户常需要分析陌生 repo）。
