## 概述

StaffDeck 是 OpenBMB（清华 THUNLP + 面壁智能）开源的企业级"数字员工"平台。核心主张不止于 AI 回答问题，而是**让 AI 能按照公司规定的流程，把一件事一步步做完**。

解决的问题：员工经验怎么留下来、重复工作怎么交给 AI、数字员工又该怎么管理。

## 核心能力

### SOP → 状态机驱动流程

将自然语言描述的 SOP 转换为状态机驱动的结构化流程：

- 多流程切换
- 上下文保留
- 可视化编辑
- 版本管理
- 分支演化

适合步骤较多、需要持续推进的业务任务（如售后处理、退款流程、工单管理）。

### 分层知识检索

按文档 → 章节 → 页面 → 摘要建立分层索引：

- 数字员工先判断信息可能出现在哪里
- 逐层定位原文
- 保留来源引用，不只有一段无出处的回答

### 工具与集成

| 能力 | 说明 |
|------|------|
| HTTP API | 调用外部工具 |
| MCP | 模型上下文协议支持 |
| 定时任务 | 自动化调度 |
| 长期记忆 | 执行链路记录 |
| 人类接管 | 遇到无法解决的特殊情况交真人处理 |
| 微信集成 | 支持个人微信和企业微信 |
| 桌面客户端 | macOS / Windows / Linux |

## 典型场景

- **售后数字员工**：提供产品资料、退款规则、订单查询工具 → 判断问题类型 → 查询订单 → 按规定处理 → 记录全过程 → 特殊情况交真人
- **流程数字化**：把员工日常的工作模式转成 AI 可执行步骤（先收集信息 → 检查资料 → 调用工具 → 输出结果）。流程变化时可重新修改，不需从头搭建

## 战略分析

### 与现有体系的对照

| 维度 | StaffDeck | PilotDeck（同组织） | WorkBuddy（已归档） |
|------|----------|-------------------|-------------------|
| 定位 | 企业数字员工平台 | 多 Agent 操作系统 | 个人生产级 Agent |
| 目标用户 | 企业团队 | 个人+团队 | 个人 |
| 流程引擎 | SOP→状态机驱动 | WorkSpace 隔离 | Harness + Skill |
| 知识检索 | 分层索引+来源引用 | 无专门强调 | 记忆管理 |
| 人类接管 | 内置 HITL | 无 | PendingApproval 审批 |
| 多平台 | macOS/Win/Linux 桌面端 | Always-on 离线干活 | Web + 终端 |
| 微信集成 | 个人+企业微信 | 无 | 无 |

### 关键差异

1. **SOP 数字化是核心差异点**：StaffDeck 最独特的价值不是 Agent 框架，而是"把员工现有的 SOP 变成状态机"这个能力。企业不需要为 AI 重新设计流程，直接拿已有的 SOP 说明书来用。

2. **与 PilotDeck 同属 OpenBMB 生态**：PilotDeck（清华 THUNLP + 面壁智能 + OpenBMB）是多 Agent 操作系统，StaffDeck 是数字员工平台——两者互补而非竞争。PilotDeck 偏"一个人管一群 Agent"，StaffDeck 偏"企业管一群数字员工"。

3. **分层的 HITL 设计**：不是简单的"AI 做不了就报错"，而是先判断是否属于人力接管范畴，再转移给真人，同时保留完整上下文。这个设计比简单的"审批"模型更贴近企业业务流程。

### 能力差距

- 当前 Hermes 生态中缺少"数字员工管理"这一层——StaffDeck 解决的是"企业怎么管理一群数字员工"（流程编排、知识索引、版本管理），而 Hermes 解决的是"单个 Agent 怎么工作"
- MCP 支持意味着 StaffDeck 可以作为 Hermes 的"企业流程层"——Hermes 通过 MCP 调用 StaffDeck 的流程，StaffDeck 管理企业规范和知识库
