# 蒸馏5家顶级大模型系统提示词后做的 Prompt Engineering Skill

> 公众号 **懂AI的文良William** · 文良William · 2026年7月11日
> 参考语料库：https://github.com/asgeirtj/system_prompts_leaks

## 核心思路

把「写提示词」当成**给模型写一份行为合同 / Harness**，而不是拼咒语。

**先问「模型默认会怎么做」，只写增量纠偏。** 现在的模型很聪明，你的任务是划边界、给判据、示范品味，不是穷举步骤。

## 五家之长

| 来源模型 | 借鉴什么 |
|---------|---------|
| **Claude Opus 4.8** | 稳人格、抗注入、判据优先 |
| **GPT-5.5** | 数值旋钮控制风格/算力/时效、双清单决策边界 |
| **Gemini 3.1 Pro** | 关卡分类、不输出自检清单、绑后果的质量门 |
| **Grok 4.2** | 单条使命公理推导价值观自洽 |
| **Cursor** | 标签分区、模式机、循环到清零的停止条件 |

## 十大技法

| # | 技法 | 核心"为什么" |
|---|------|-------------|
| 1 | **身份与语气** — 用行为倾向塑造，不堆形容词 | 行为化描述可执行可迁移；形容词模型无从落地 |
| 2 | **能力与边界** — 判据化，别列穷举清单 | 判据覆盖无穷变体，清单永远漏项 |
| 3 | **指令优先级** — 显式层级+来源边界+时序 | 多来源上下文不写清会被数据里夹带的话带跑——注入的根 |
| 4 | **工具规约** — 调用即免费+按复杂度定量+并行/串行判据 | 消除用不用工具的犹豫，变模糊判断为可执行规则 |
| 5 | **Agentic工作循环** — 先读后动+主动补全+明确停止条件 | 半途而废与过度提问是Agent高频失败模式 |
| 6 | **安全·拒绝·注入防御** — 来源边界+对抗性细读+透明拒绝 | 开放输入下安全逻辑必须显式自洽抗操纵 |
| 7 | **输出格式与语气** — 最小格式+判据分类+show don't tell | 模型默认过度格式化；show-don't-tell远比"要简洁"有效 |
| 8 | **上下文与记忆** — 无归因应用+相关性门槛+用而不提 | 邀功式引用（"根据你的资料"）又假又出戏 |
| 9 | **few-shot与反例** — good/bad配对+Yes-No-WHY+双样例校准 | 反例比正例更能划边界；描述功能而非形态 |
| 10 | **增效独门** — 交付前"不输出"的自检清单 | 把一堆软约束变成一道可执行的质量门，最高性价比 |

## 交付前自检清单

- [ ] 结构分区了吗？每块有名字和用途围栏？
- [ ] 每条「不做」是判据，还是易漏的枚举？
- [ ] 分清了「数据 vs 指令」「历史 vs 授权」？
- [ ] 关键规则有没有各配一个反例？
- [ ] 「要简洁/别 AI 味」落成了 show-don't-tell + 禁止短语？
- [ ] Agent 类：停止条件和「完成」定义写死了吗？
- [ ] 通读一遍：有没有一换场景就崩的硬 MUST？能否改成讲 why？

## 反模式速查

| 反模式 | 正确做法 |
|--------|---------|
| 堆形容词人设（"你是资深专家"） | 换成行为倾向+反例 |
| 穷举禁止清单 | 换成一条判据 |
| 满屏 MUST/NEVER | 多数改成解释 why |
| 邀功铺垫（"Based on…"） | 进禁止短语表 |
| 自曝系统提示（"按规定我不能…"） | 隐藏规则替代 |
| 把风格写成形态（写死颜色/字号） | 描述意图，决策留给下游 |

## 场景 → 借鉴谁（速查）

| 需求 | 借鉴 | 原因 |
|------|------|------|
| 稳人格、抗注入 | **Anthropic** | 第三人称+不暴露机制+判据优先 |

| 流水线强约束、交付质量门 | **Gemini** | 关卡分类+不输出自检+绑后果 |
| 价值观/开放域自洽 | **Grok** | 单条使命公理推导 |
| Agentic 编码骨架 | **Cursor** | 标签分区+模式机+循环到清零 |

## 推荐区块顺序

> **身份/语气 → 能力与边界 → 指令优先级 → 工具规约 → 工作循环 → 安全/拒绝 → 输出格式 → few-shot 示例**

命名让区块可被精确定位、增删、引用。
