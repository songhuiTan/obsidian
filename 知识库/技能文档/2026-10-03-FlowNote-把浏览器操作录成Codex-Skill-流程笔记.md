## 一句话结论

**用 Chrome/Edge 扩展把网页上的一次人工操作录下来（含多分支），导出 JSON，再让 Codex 整理成 Skill 反复执行。** 它要解决的不是"AI 能不能操作浏览器"，而是**RPA 的确定性怎么和 AI 的容错性拼在一起**。

## 它到底怎么工作

```
网页操作演示
    ↓
FlowNote 扩展记录步骤（点击/填写/选择/勾选/提交/Enter/Esc/跳转/拖动/滚动/iframe）
    ↓
人工检查、补充说明、插入等待、录制条件分支
    ↓
导出 JSON（schema v3）
    ↓
Python 转换器校验 + 整理 → Skill 草稿
    ↓
Codex 理解流程、补齐运行参数、观察实时页面并执行
```

**分工很清晰**：扩展只管**记录**，转换器只管**校验**，Codex 负责**理解 + 执行**。扩展本身**没有任何自动判断和回放能力**。

### 支持的操作类型

| 类别 | 覆盖 |
|------|------|
| 基础交互 | 点击、填写、选择、勾选、表单提交、Enter/Escape、页面跳转 |
| 拖动 | 滑块（起点终点相对位置）、商品排序/HTML 拖放（含前后位置）、普通元素拖放、Canvas 轨迹（最多 24 个简化点） |
| 滚动 | 页面与容器滚动，停止滚动 300ms 后记录最终位置，连续滚动合并 |
| 弹层 | 自动发现可访问的 HTTP(S) iframe，支持跨站、动态加载、嵌套框架 |
| 条件分支 | 从任意步骤之后录制另一条路线，最多 20 个，支持嵌套 |
| 等待 | 任意两步之间插入 1～3600 秒固定等待 |

### 条件分支的表达方式

主流程是 `1 → 2 → 3 → 4 → 5`，第 3 步后可能出现"暂无数据"：

```
1 → 2 → 3 ┬→ 4 → 5       主流程
          └→ 6 → 7 → 8   当页面显示暂无数据时
```

**关键语义**：分支发生在选中步骤**之后**；满足条件就走分支并跳过原路线剩余步骤；**没有条件匹配就继续原路线；分支结束后不会自动接回原路线**。多个条件同时匹配或无法判断时，需人工澄清。

> 这一段是所有 RPA 工具都做不好的地方。传统 RPA 用固定规则判断，AI 用语义判断——FlowNote 的选择是**把判断权交给执行时的 Codex**，扩展只负责告诉你"这里可能分叉"。

### 自解释拖动 JSON（最聪明的一个设计）

坐标不只是裸数字，而是**直接声明坐标系、原点和重放策略**，不需要 AI 猜：

```json
{
  "action": "drag",
  "dragType": "range",
  "coordinateSystem": {"unit": "ratio", "origin": "top-left"},
  "start": {"x": 0.2, "y": 0.5, "relativeTo": "source"},
  "end": {"x": 0.8, "y": 0.5, "relativeTo": "source"},
  "startValue": "20",
  "targetValue": "80",
  "replayStrategy": "set-value-first"
}
```

`ratio` 是 0~1 的元素内相对比例。**滑块优先用运行时目标值 `set-value-first`，坐标只作为备用提示**——这是懂行的人写的：滑块的正确做法是设值，不是拖到某个像素。

拖动判定：主指针移动超过 **8 个 CSS 像素**才算拖动，避免把点击误判成拖动。

### 隐私设计

- 录制数据存在**扩展本地存储**，扩展**没有网络上传功能，也不读取 Cookie**
- **默认不保存输入值**，而是转为后续运行参数；只有开启「保留填写示例」才记录
- **密码、验证码、密钥等敏感字段启发式识别后不保存**
- 网址查询参数值替换为占位符，网址片段不保留
- **路径、标签、页面文字仍可能含业务数据，导出前需自查**
- 网站黑名单：按整站匹配（含子域名），最多 100 个，存本机立即生效，清除录制不清除黑名单

## ⚠️ 已知限制（作者自己列的，诚实度加分）

- 不支持 `about:blank` / `srcdoc` / `blob` 特殊框架、关闭的 Shadow DOM、浏览器设置页、PDF 阅读器
- Canvas 只存相对轨迹，回放精度取决于画布尺寸、内容状态和浏览器工具的坐标能力
- **文件拖放和原生文件选择框不保存路径和内容**，执行时需重新提供
- **下载按钮的点击会记录，但下载的文件和下载完成事件不录制**——这是最大的盲点：任务"看似成功"但文件可能没下来
- 单段上限约 1500 事件 / 3.5 MB，超限自动停止，长流程需分段

> 作者明确写着：**"转换完成的 Skill 初始状态为『需要实际运行验证』——录制到一次点击并不代表业务操作成功，执行时仍需检查下载文件、查询结果或页面反馈。"** 这个态度比多数同类项目诚实。

## 安装与使用

### 1. 装浏览器扩展（首次需手动加载）

1. 把 `extension` 文件夹放到**固定位置**（别放临时目录或 Codex 版本缓存里）
2. `chrome://extensions` 或 `edge://extensions` → 开启开发者模式 → 加载已解压的扩展程序
3. 选中**直接包含 `manifest.json`** 的 `extension` 文件夹
4. 更新时：扩展页点「重新加载」，如要求确认新增网站权限需确认一次，再刷新目标页（先保存未完成内容）

### 2. 装 Codex 插件

```powershell
codex plugin add windows-record-replay@personal
```

> 内部 ID 仍叫 `windows-record-replay`（为兼容已安装的录制文件），显示名才是「FlowNote · 流程笔记」。

### 3. 录制流程

1. 打开目标网站并**完成登录**
2. 点扩展，填流程名称和完成目标 → 开始录制当前页
3. 正常操作；页面右下角显示录制提示，工具栏显示 `REC`
4. 切到新标签页后，需点「继续录制当前页」；同标签页的普通跳转和刷新会自动继续
5. 停止录制 → 检查步骤、删多余、加等待、补日期/命名/成功判断规则
6. 导出 JSON，交给 Codex：

```
使用 windows-record-replay，把这份录制整理成下载经营日报的 Skill。日期作为参数。
```

7. 以后使用：

```
使用 daily-report-download，下载昨天的经营日报，保存到我指定的文件夹。
```

### 4. 本地转换（不依赖 Codex）

```powershell
powershell.exe -NoProfile -File .\scripts\Convert-Recording.ps1 -Recording "C:\path\wrr-recording.json" -Name daily-report-download
```

输出默认到 `%USERPROFILE%\.codex\skills\daily-report-download`。或直接：

```text
python scripts/recording_to_skill.py recording.json --name daily-report-download --output ./generated-skills
```

**只需 Python 3.10+ 标准库**。重复名称会报错，已有 Skill 不会被覆盖。

## 战略分析

### ① 评论区那个质疑是对的，但答案不在工具里

> 「这个和直接让 agent 自己跑一遍，然后把能脚本的地方都设置成脚本，有啥区别吗」

**区别在责任边界，不在能力。** 纯 AI 跑一遍的问题不是跑不通，是**每次跑法都不一样**——同一件事今天点 A 路径明天点 B 路径，出了问题无从复现。FlowNote 的价值是把"确定性"钉下来：**哪些步骤必须一模一样（登录、提交、下载文件名规则），哪些步骤允许 AI 临场判断（页面长什么样、有没有"暂无数据"）**，录制过程强制你把这条线画出来。

而这个切分**正是我们目前在 Hermes 里做自动化最缺的一层**。现在让 Agent 干重复性网页活，全靠 prompt 描述，跑三次三种偏差，且没有回溯依据。FlowNote 的 JSON 至少是一份**可审计的流程图**。

### ② 它比 Playwright Codegen 多出来的那一层

Playwright 录制出来的是**线性硬编码脚本**：选择器固定、没有分支、没有"这里该问 AI"的标记。页面一改就全废。FlowNote 录出来的是**意图 + 语义定位 + 分叉点**，具体怎么走交给执行时的 Codex。

代价也很明显：**它不能独立运行**。没有 Codex（或 Kimi 浏览器扩展这类能控制浏览器的工具），这套东西一步都走不了。这是「录制器」不是「RPA 引擎」。

### ③ 32 star + 无 License —— 别急着装在业务上

- **无 License = 默认保留所有权利**。拿来自己用没人管，但做商业交付、嵌进公司流程、二次分发都是法律裸奔。要用先找作者要授权或等它加 License
- **视频发布第二天就停更**（最后推送 2026-10-02），32 star 说明没有社区在踩坑。遇到站点兼容性问题基本只能自己修
- 目标是 **Windows + Chrome/Edge**，**macOS 和 Safari 不在支持范围**。我这台是 macOS，装了也用不了扩展

### ④ 但"录一次 → 可审计 JSON → 交给 Agent"这个模式值得抄

不必用它的代码，值得借它的**思路**：

1. **把"能做出来"和"能稳定做出来"分开记账**——跑通一次不算数，要能复现
2. **拖动/滑块类操作优先设值而不是模拟鼠标轨迹**（`replayStrategy: set-value-first`）
3. **录制时就标注分叉点**，而不是事后在 prompt 里补救
4. **"下载文件"这类只有副作用没有页面反馈的动作，必须单独校验**。FlowNote 明确说它录不到下载完成事件——这个坑在任何 Agent 自动化里都存在

### ⑤ 关于"电商人"标签

视频打了 `#电商人` 标签，评论区有人直接问委托开发报价。**这提醒一件事**：这类工具的真实买家不是开发者，是**每天在后台重复导报表、改价格、传商品的运营**。对他们来说"录一遍"就是全部的技术门槛；对开发者来说这工具太薄。

我们（Hermes）在这个方向上的位置应该更靠前：不是做录制器，而是**让录制出来的流程能直接被 Agent 接管并自我校验**。
