## 概述

作者作为一名 3 年自媒体创作者，在发现基于 Coze Skill 的小红书爆款数据背后来源于 **RedFox** 平台后，基于 RedFox 的 API 和 Skill 体系，结合 Codex 开发了一套全平台自媒体管理应用——**「灵感熔炉」（Inspiria）**，并已开源。

核心场景：通过 RedFox 的实时多平台数据（公众号、小红书、抖音、B站等），驱动选题、创作、跨平台重构、账号追踪、违规检测和复盘等全链路工作流。

## RedFox 是什么

RedFox 是一个新媒体数据接口平台，收集全网（抖音、小红书、公众号、视频号、快手、B站、头条）的实时数据，清洗结构化后开放为 API 和 Skill，让创作者创作时有真实数据可参考。

| 特性 | 描述 |
|------|------|
| 数据时效 | 实时数据，不会给 2026 年的文章添加 2023 年的网络烂梗 |
| API 费用 | 调用一次 0.4-0.6 积分（≈ 4-6 分钱），无套餐无月度门槛 |
| Skill 体系 | 爆款内容解析、数据分析、黑马账号、10W+、热点追踪推荐等，全链路开源 |
| 新用户 | 送 200 积分，起步成本为零 |

## 灵感熔炉（Inspiria）功能拆解

### 1. 热榜

定时任务每天凌晨跑一次，抓取全网自媒体平台 Top 爆款信息，存入本地数据库。包含：

- **7/14 天趋势分析**：什么内容在增长、什么在冷却
- **赛道聚合**：按领域（AI 资讯、NAS、小红书等）整合热点
- **聚合搜索**：按关键词搜索跨平台爆款数据（如搜"AI Agent"可获取近期所有 10W+ 内容）
- **本地落库**：调用一次 API 后历史数据保存在本地，后续分析不消耗额外额度

### 2. 灵感（选题库）

基于热榜数据，通过 LLMs 二次筛选分类，自动生成选题及内容概要。每个选题下方附**爆款参考来源**——从 10W+ 标题内容反推平台推荐算法。

作者还整合了本地 Obsidian、Notebook，结合存稿和热点进行撰写，并计划结合账号属性和发布赛道做更精准的选题推荐。

### 3. 跟踪

基于 RedFox 的**红狐分数**（对标新榜榜单），从内容健康度、用户活跃度、核心数据、运营规范性等维度评分，支持：

- **账号详情**：综合评分、指数、均阅读、四维评分、最近作品
- **周复盘**：对比选题、标题、封面、发布时间四个维度
- **爆款拆解 + 选题表生成 + 多平台重构分发**
- **订阅追踪**：常规订阅（定时拉取最新文章）+ 关注订阅（竞品趋势分析）

### 4. 跨平台重构

| 能力 | 说明 |
|------|------|
| 平台适应性 | 通过 RedFox 多平台爆款数据 + LLMs 分析爆款风格，公众号长文 → 小红书短平快 |
| 热点重构 | 判断文章是否可以结合当下热点趋势去改写 |
| 封面生成 | 接入 RedFox 的 Image2 生图 API，自动生成各平台尺寸封面 |
| 违规词检测 | 发布前对标题、正文、图片做全面检查（作者亲历被追嘎 3 篇文章后重视） |

### 5. 跨 Agent + Skill 交互

系统内置 Agent 交互模块，可接入 Claude Code、Codex、Kimi Code、OpenClaw、Hermes 等工具使用。预装 RedFox 所有官方 Skill，当系统单独功能无法满足时可调用 Skill 进行二次工作。Skills 也可安装到 MiniMax Code 桌面端等 Agent 生态中。

### 6. 定时任务与额度查询

所有增量更新、热点刷新做成定时任务配置（支持 Cron 格式），可修改、开启、关停。API 调用用量和余额查询内置在设置中。

## 战略分析

### 与现有工具链的对照

| 维度 | 灵感熔炉 (Inspiria) | 现有体系 |
|------|--------------------|----------|
| 数据源 | RedFox API（结构化、实时、全平台） | Last30days CN（微博/小红书/B站/知乎等8平台）、MediaCrawler（Playwright模拟登录） |
| 选题 | 热榜 → LLM 筛选 → 选题库 | viral-topic Skill（低粉爆款采集） |
| 跨平台重构 | 基于爆款数据 + LLMs 的平台适应性改写 | 手动或 LLM 直接改写 |
| 本地存储 | 本地数据库落库 | 无系统化本地存储 |
| 违规检测 | RedFox 违规词检测 API | 无 |
| 账号追踪 | 红狐分数 + 趋势分析 | 无 |
| 定时任务 | Cron 格式调度 | Hermes cronjob |
| Agent 交互 | Codex/Claude Code/Hermes/OpenClaw 均可 | Hermes Agent 为主 |

### 关键差异与整合可能

1. **RedFox API vs Last30days CN/MediaCrawler**：RedFox 是商业数据平台，提供结构化、实时的 API（调用一次 4-6 分钱），无需维护爬虫。Last30days CN 和 MediaCrawler 是自建爬虫方案，数据更灵活但需要维护登录态和反爬。两者不是替代关系——RedFox 适合高频、标准化的数据需求（热榜、爆款分析），自建爬虫适合定制化的数据采集场景。

2. **跨 Agent 交互模块**：项目内置了一个"Agent 交互模块"，可以接入多种 Agent 工具，包括 Hermes。这个模式值得关注——它相当于在自建平台中嵌入了一层 Agent 编排层，Skill 作为可插拔能力。

3. **违规词检测**：当前 Hermes 生态中缺少这个能力。RedFox 的违规词检测 API 如果可单独调用，可以补充到内容发布流程中（尤其是公众号/小红书写作场景）。

4. **账号复盘系统**：从红狐分数的四维评分到周复盘、竞品追踪，这是一套完整的内容运营分析工具。如果 Hermes 要扩展"内容运营"场景，这套思路有参考价值。

### 局限

- RedFox 是数据源依赖——如果平台关闭或改变收费策略，Inspiria 的功能基础会受影响
- 项目基于 Codex 开发，本质上是一个前端应用 + 后端 API 的 Web 应用，不是 Agent Skill 体系
- 违规检测和账号分析的数据来源同样依赖 RedFox，独立运行能力有限
