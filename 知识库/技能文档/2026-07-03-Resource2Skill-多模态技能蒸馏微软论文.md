## 文章概要

微软论文 **RESOURCE2SKILL**（arxiv: 2606.2953）——把教学视频、代码仓库、文章教程、参考作品等人类创作资源，自动蒸馏成 Agent 能理解、能检索、能执行的技能库（Skill Wiki）。通过四步工程管线解决了"最好的教程摆在那，Agent 却看不到"的问题。

## 核心管线（四步）

### 第一关：从四种资源提取技能

四种来源：
- **教学视频** → 操作顺序 + 视觉效果
- **代码仓库** → 可执行的调用模式
- **文章教程** → 概念解释 + 适用场景
- **参考作品** → 风格 + 质量基准

提取由领域特定查询驱动（如"Blender 材质节点编辑"），VLM 提取关键帧/代码片段/文字描述/元数据。

**五道质量门控**：完整性、来源可追溯、去重、多模态信息一致、代码可执行。通不过的直接丢弃。

### 第二关：层级 Wiki 树组织

- Flat list 比层级 Wiki 低了 **2.5~8.2 个百分点**
- 每个技能条目包含**三个互补字段**：
  - **文本**：做什么、什么时候用
  - **视觉**：缩略图、截图、渲染预览
  - **代码**：可直接执行的程序片段
- 只保留纯文本，平均分掉 **3.9 个点**

### 第三关：METABROWSE 两层选择

1. **词汇层初筛**（BM25）— 对技能名称/标签/描述/层级路径做关键词匹配，从几千条缩到 20 条候选。BM25 比向量检索高 **2.9 个点**。
2. **语言模型精选** — 对 20 条候选做子集选择（选 0~5 条，不强制 top-K），而非排序。

METABROWSE 在所有领域排第一（平均 **68.9%**），比纯 BM25 高 2.9 点，比 BM25+向量混合高 4.7 点。纯向量检索最差（60.0%）。

### 第四关：执行与在线补漏

- 技能代码通过 MCP 协议直接执行（LLM 不做翻译）
- 参考型技能（无代码）：Agent 根据文字+视觉参考自行写代码，来源保留可审计
- 在线补漏：离线库覆盖不到时触发，+21.6 点（刻意构造的盲区测试）

## 评测结果

| 维度 | 结果 |
|------|------|
| **覆盖领域** | PPT设计、Web页面、Excel制表、Blender 3D、CAD二维绘图、UE5实时3D、Reaper音频制作 |
| **模型** | GPT-5.5 / 5.4 / 5.4 Mini / 5.4 Nano |
| **WSKILLS vs W/OSKILLS** | 28/28 格子全赢，平均 **56.8% vs 45.0%**（+11.9 点） |
| **vs 最强 Harness** | 26/28 格子 WSKILLS 赢 |
| **人类偏好盲测** | 五评审 40 配对，WSKILLS 赢 **83.3%** 非平局 |
| **提升最大** | UE5（+30~40 点） |
| **提升最小** | Reaper（裸 Agent baseline 较高） |

### 技能库规模

- 200 条附近开始饱和（Excel +14.2 点，最少的 Reaper 也 +3.1）
- 400 条后增速几乎持平

## 关键洞察

- 层级 Wiki > flat list，因为检索时把语义空间约束到相关子树
- 结构化稀疏性比向量检索的数学稀疏性更可控
- 多模态条目三视图各司其职，不互相替代
- 在线补漏是 gap-filler 而非 booster，平时不动
- 五道质量门控是整个系统的稳定底座

> 如果说 Anthropic 的 Agent Skills 定义了"技能应该长什么样"，那 RESOURCE2SKILL 在回答"技能应该从哪来"。
