## **🧠 第二步：安装Hindsight，替代内置记忆**

### **为什么内置记忆不够用？**

Hermes内置的MEMORY.md存在两个致命问题：

| **问题** | **说明** | **影响** |
| --- | --- | --- |
| 字符上限 | 约2200字符（~500字） | 长期记忆容量严重不足 |
| 写入机制 | 只在"觉得重要"时才写入 | 主观判断，经常漏掉关键信息 |

### **Hindsight：真正的长期记忆方案**

**Hindsight**是一个专为AI Agent设计的记忆管理系统，核心能力：

- ✅ **自动提取**：从每轮对话中提取实体、事实、关系、时间戳
- ✅ **知识图谱**：结构化存储，建立实体之间的关系
- ✅ **自动注入**：新会话时，自动注入相关记忆到上下文
- ✅ **无上限**：云端存储，记忆容量几乎无限

#### **配置步骤**

# 1. 配置Hermes使用Hindsight

hermes memory setup

? 选择记忆后端：# 选择 "Hindsight"



# 2. 获取Hindsight API Key

访问 https://ui.hindsight.vectorize.io/connect

注册账号 → 获取免费API Key



# 3. 将API Key添加到Hermes配置

nano ~/.hermes/config.json

添加："hindsight\_api\_key": "YOUR\_API\_KEY"



# 4. 验证配置

hermes memory status

✅ auto-recall: enabled

✅ auto-retain: enabled

**⚠️ 注意事项：**

1. Hindsight免费版有存储上限（通常100MB），超出需付费

2. API Key妥善保管，不要上传到GitHub等公开平台

3. 如果网络无法访问Hindsight服务器，记忆功能会失效

## **💰 第六步：精细管控Token消耗**

### **为什么Token优化很重要？**

Hermes使用的大模型（如Claude、GPT-4）按Token计费。如果不加管控，Token消耗会非常快：

- 长对话历史：每次都把历史消息发给模型，消耗巨大
- 工具调用：每次工具调用都会消耗Token（输入+输出）
- 大文件处理：一次性读取整个文件，Token爆炸

### **工具1：RTK（Rust Token Killer）**

**功能：**压缩终端命令的Token消耗60%-90%

**原理：**精简命令输出，只保留关键信息

# 安装方法A：Homebrew（macOS）

brew install rtk



# 安装方法B：一键脚本（Linux/Windows）

curl -fsSL https://raw.githubusercontent.com/rtk-ai/rtk/refs/heads/master/install.sh | sh



# 集成到Hermes

rtk init -g

✅ RTK已集成到Hermes，Token消耗降低60%-90%

### **工具2：Tokscale**

**功能：**实时监控Token消耗，拆解去向

**特点：**可视化界面，按模型/会话/工具调用分类

# 安装

npx tokscale@latest



# 只看Hermes的Token消耗

tokscale --hermes



# 输出示例

会话1：1234 tokens (45%)

- 用户输入：234 tokens

- AI回复：567 tokens

- 工具调用：433 tokens

会话2：...

### **工具3：hermes-hudui**

**功能：**Web UI界面，14个Tab，精细化管理

**特点：**图形化界面，按模型/会话/工具调用拆解Token去向

# 安装

hermes tools install hermes-hudui



# 启动Web UI

hermes hudui start

✅ HUD UI已启动：http://localhost:8080

**⚠️ 重要提醒：**

很多人觉得"Token优化以后再说"，结果账单来了"哭死"！

建议在第一步配置Hermes时就启用RTK和Tokscale，不要等到账单爆炸再后悔。
