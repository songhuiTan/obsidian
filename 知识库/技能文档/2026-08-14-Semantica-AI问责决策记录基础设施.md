## 概述

用 AI Agent 做正经事的团队越来越多，但问题随之而来：**AI 批了一笔贷款、调了一个剂量，回头问它为什么这么干，没人答得上来。** 模型说不上来，系统里也没地方查——"当时是怎么考虑的"压根没被留下来。金融、医疗行业尤其致命：监管隔几个月回头问一句为什么，你得拿得出东西。这就是 **AI 问责**。

**Semantica**（登顶 GitHub Trending）：不是又一个 Agent 框架，也不是又一个向量库，而是**垫在你现有技术栈底下的一层基础设施**——原来的模型、向量库、Agent 框架都不用动，它补的是一直缺着的那一块：**决策记录、因果推理、来源追溯、审计导出**。官方自称"**给 AI Agent 用的开源版 Palantir**"。

**关键特性**：建图、推理、溯源这些核心环节**不需要调大模型，是确定性运行的**——同样的数据进去，结果一样，每一步都能展开给人看。拿去给审计看的东西，确定性最要紧（总不能监管问一次，系统给一个新答案）。

## 功能详情

### 1. 决策记录：每个决定都变成一条能查的账（最核心）

- 每次 AI 决策记成图里的一个节点：**场景、理由、结果、置信度**
- 决策之间标因果关系：谁导致谁、谁影响谁、谁参考了哪个先例
- 查来龙去脉：调一个接口拉出完整因果链
- 按语义搜历史先例
- 分析决定影响了下游哪些环节
- 审计导出 **W3C PROV-O 格式**（合规框架普遍接受的标准格式）

> 一句话概括：**决策在这个系统里不是一行刷过去就没影的日志，而是一个能被反复查询、能被追问的对象。问责就是这样落到实处的。**

### 2. 上下文图谱：不只回答"像不像"，还回答"连不连着"

- 传统 RAG 靠向量相似度回答"什么东西和它像"；Semantica 回答"**什么和什么连着、怎么连的、为什么连的**"
- 人、公司、合同、事件、决策都是节点，关系是边；**多跳关联**（隔三层关系也能图遍历找到）是向量检索很难做到的
- 每条边带时间属性：可查图在过去某个时间点长什么样——**知识库历史快照，想回放哪天就回放哪天，不用重跑数据**

### 3. 冲突检测：两份数据打架，它会先标出来

- 多来源灌数据必然打架（A 系统写 CTO，B 系统写技术副总裁）
- 大多数方案后写覆盖先写，错数据悄无声息留下；Semantica **先检测、标严重程度、按策略处理**（信来源可信度高的/信最新的/多来源投票）
- 重复实体：先检测、再合并，保留来源记录；数据脏不脏、脏在哪里一查就知道

### 4. 来源追溯：每条事实都能问一句"你从哪来"

- 每个实体/关系挂来源：来自哪个文件、第几页、哪个系统、什么提取器、置信度多少
- 可反问任何一条数据的完整来历，**顺着记录一直追到原始文档**

### 5. 规则推理：写在明处的逻辑，推理路径能展开看

- 内置规则引擎："金额超一万 + 涉及某些地区 → 标记待审查"
- 结论不是黑箱蹦出来的：**每一步推理路径都能展开**，说清依据哪条规则、哪些事实
- 对问责和合规关键："能被解释的规则，才是能拿去跟监管对话的规则"

### 6. 数据接入和存储：进得来，也出得去

- 接入：本地文件、网页、数据库、Kafka 消息流、Git 仓库、邮件；**Databricks 和 Snowflake 有现成连接器**（仓库表直接变图节点，带血缘信息）
- 存储不挑：Neo4j、AWS Neptune 等属性图库，或 RDF 三元组库 + 向量库，**换后端不用改业务代码**
- 模型服务：主流都能接，DeepSeek 和 Ollama 本地模型在列
- 导出：RDF、JSON-LD、Parquet、Cypher

### 7. 在 Codex 里直接用（对开发者最实用）

自带 MCP 服务器 + Codex 现成插件包，**开发时让 Codex 顺手把重要决策记进图谱**：

```bash
python -m semantica.mcp_server
```

`~/.codex/config.toml` 加：

```toml
[mcp_servers.semantica]
command = "python"
args = ["-m", "semantica.mcp_server"]
```

重启 Codex 后挂进 **16 个工具**：记决策、查决策历史、找先例、拉因果链、加实体、跑规则推理、导出图谱。

**使用示例**：讨论完技术选型直接说「把刚才的决定记一下：支付模块的 ORM 选 SQLAlchemy 不选 Django ORM，原因是项目本来就用 FastAPI，团队更熟，置信度 0.9」→ 调用 `record_decision` 写进图谱。过几个月新同事问「当时为什么选 SQLAlchemy」→ 图谱翻出记录连理由；一串关联决定还能拉完整因果链。

**价值洞察**：开发过程里的口头决策是最留不下来的东西——群里说一句就这么定了，三个月后没人记得为什么。现在讨论完顺手记一句，来龙去脉就存住了。

### 8. 可视化和命令行

- 浏览器可视化工作台：图结构、本体层级、时间线交互查看，因果链一层层点开
- 命令行工具：装包自带，数据接入、建图、推理、导出全终端完成；建议先跑 `semantica doctor` 自检环境

## 快速开始

```bash
pip install semantica
semantica doctor    # 自检环境
```

```python
from semantica.context import ContextGraph

graph = ContextGraph(advanced_analytics=True)

decision_id = graph.record_decision(
    category="vendor_selection",
    scenario="为合规业务选云服务商",
    reasoning="签了数据处理协议，团队也熟",
    outcome="selected_aws",
    confidence=0.93,
)

chain   = graph.trace_decision_chain(decision_id)               # 查完整因果链
similar = graph.find_similar_decisions("云厂商选择", max_results=5)  # 找历史先例
```

## 使用场景

- **银行信贷**：AI 批贷款，从申请、审批到定利率整条决策链被记录，监管随时能查
- **医疗**：用药审查、剂量调整必须事后说得清依据
- **企业知识图谱**：数据已在 Databricks/Snowflake 的团队，连接器现成
- **合规风控**：按标准格式导出可直接交出去的审计材料
- **多 Agent 系统**：几个 Agent 读写同一张上下文图，不用各记各的，出问题知道找哪条记录
- **开发团队**：技术选型、架构决策等口头约定用 Codex 顺手记进图谱

**不适合**：只写聊天机器人或简单文档问答——没必要增加复杂度。

## 最后聊聊（作者观点）

> 问责这个事，现在大家都在讨论 AI 该怎么管，我觉得**管的前提是先能看见**——看见它做了什么、为什么这么做，然后才谈得上负责。Semantica 做的就是"看见"这一层。如果你的 Agent 做的决定需要经得起几个月之后的一句"为什么"，值得认真试试。

## 战略分析

**Semantica 是"AI 问责基础设施"的稀缺开源实现**，与知识库已归档内容形成多线呼应：

| 本文能力 | 知识库已有对应 |
|---------|--------------|
| 决策记录 + 因果链 | 生产级企业知识库指南（日志可审计、溯源）、Agent 可观测性 |
| 冲突检测（先检测后处理 vs 后写覆盖） | gbrain 的 find_contradictions（suspected-contradiction 探测） |
| 来源追溯（追到原始文档） | 生产级知识库（引用来源是信任机制）、gbrain 溯源 |
| PROV-O 审计导出 | 企业级合规/审计需求 |
| MCP + Codex 集成 | 近期归档的 Codex 增强系列（GitHub 搜索、代码图谱、SkillsGate） |
| 确定性运行（不调大模型） | gbrain 的零 LLM 成本自动知识图谱设计 |

**核心启发：**

1. **"决策记录跟着开发流程走"是最实用的切入点**——通过 MCP 让 Codex 顺手记决策，解决了"口头决策最留不下来"的真实痛点。这对用户的开发实践有直接价值：技术选型、架构决策随手记录，几个月后可回溯。**这可以成为 Hermes skill 的补充实践**（对话中做决策时主动沉淀）。

2. **"确定性运行"是审计场景的硬要求**——建图/推理/溯源不调大模型，同输入同输出，每一步可展开。这与 gbrain 的"结论摘要+时间线 Markdown 结构、零 LLM 成本知识图谱"设计哲学一致：**可审计的系统不能依赖概率输出**。

3. **冲突检测"先检测后处理"优于"后写覆盖"**——与 gbrain 的 find_contradictions、知识库"数据治理（文档生命周期）"主线呼应；对 Hermes 的 TencentDB 记忆四层系统同样适用：多来源记忆冲突时应显式标记而非静默覆盖。

4. **多跳关联 vs 向量检索**——Semantica 图谱回答"连不连着"，向量检索回答"像不像"，两者互补。这正是 gbrain 混合检索（向量+图谱+关键词）的设计依据。

5. **定位清晰**：这是基础设施层而非 Agent 框架——垫在现有栈底下补"决策记录/因果/溯源/审计"。**对用户的 Hermes + Obsidian 体系**：可作为"决策日志"外部补充，尤其适合需要长期可追溯的场景（投资、创作、知识管理决策）。

**一句话**：Semantica = 给 AI Agent 用的"账本"基础设施（开源版 Palantir），决策记录/因果链/冲突检测/来源追溯/规则推理 + PROV-O 审计导出，确定性运行可展开验证；"管的前提是先能看见"是其核心主张。
