# MindForge：基于 Karpathy LLM-Wiki 的知识铸造平台

> **一句话**：sudden 用 3 个月 vibe coding 打造的基于 Karpathy LLM-Wiki 的开源知识铸造平台——把分散的论文、报告与经验，铸造成结构化、可连接、可演进、可对话的知识网络，指导做研究、找创新、搞创作、生灵感。本地部署，数据不出域。

## 项目信息

- **开源地址**：https://github.com/Suddennebbus/MindForge
- **介绍页**：https://mindforge-intro.pages.dev/
- **作者**：是sudden哦（sudden的AI日常），2026-08-26 开源
- **背景**：作者 4 月拆解 Karpathy LLM-Wiki → 实践发现坑点 → 3 个月 vibe coding → 社区催更下开源（首次独立开源完整系统）

## 核心闭环

> 探索方向 → 生成计划 → 收集资料 → **人审核入库** → AI 摄入 → 形成 Wiki → 对话 / 再探索

信息不再只是被"存起来"，而是被**结构化、链接化、可对话化**，持续增值为知识资产。

## 传统知识库之痛（问题定义）

- **知识沉寂**：文档越堆越多，检索靠关键词，找得到却读不完，读完也难提炼结论
- **有信息，没洞察**：上百份资料回答不了"这个领域研究到什么程度了？我们还缺什么？下一步该做什么？"
- **各自为战**：立项、调研、写方案从零开始手搓，重复劳动严重
- **知识质量无人把关**：原材料污染知识库；规模扩大后结构腐化（概念冲突、信息缺口、孤立页面）

> 当信息不再稀缺时，真正稀缺的变成了洞察力、方向感，以及把信息转化为行动的能力。

## 核心亮点

### 🤝 HITL 人机协同贯穿全程
不做"黑盒全自动"知识库——AI 再强，判断权始终在人手里。

### 🔨 知识铸造：入库即完整，拒绝压缩式摘要
- 一份资料入库后，AI 通过**"先规划、人确认后再生成"**的两阶段摄入流程，自动拆分为多个结构化 Wiki 页面
- 页面遵循"摘要 + 核心方法 + 关键事实 + 来源"结构规范
- 作者、arXiv ID、DOI 等元数据**从 PDF 中真实提取注入，杜绝模型编造引用**
- 产出的是接入知识网络的完整信息单元，而非一段被压缩的摘要

### 🧭 研究指导：引导式访谈 → 可执行研究计划
- 输入研究方向，AI 通过**选择题式访谈**澄清真实需求
- 结合知识库上下文与网络/学术调研，输出含目标、方法、里程碑、风险、研究问题、预期贡献的完整研究计划
- 计划附带**建议阅读清单，一键下载到待入库**，直接进入"审核 → 入库 → 摄入"主流程

### 🔭 知识探索：发现缺口
- 输入模糊方向（如"智能体安全"），AI 基于全库做全局分析
- 输出三栏：**已有知识覆盖盘点 / 按优先级排序的知识缺口 / 可执行研究建议**
- 有价值的建议一键生成研究计划；探索历史自动保存可回溯

### 🕸️ 知识图谱
- 页面间 [[slug]] 双向链接，形成可导航、可溯源的知识网络
- 图谱视图：缩放、悬停高亮关联节点、点击跳转、关键词筛选（匹配节点+一度邻居）
- 单页图谱视角：聚焦某个知识节点的全部关联
- **关联查询纯本地计算，零 LLM 调用，秒开**

### 💬 专家问答：好答案一键沉淀为知识
- AI 结合库内知识作答：流式输出、Markdown 渲染、**来源标注可点击溯源**
- 好答案一键生成综合页面，自动完成摄入流程——**反哺知识库，越用越聪明**

### 🩺 知识体检（Lint）：一键修复 + 人机协同
- 检测结构腐化：概念冲突、缺失反向链接、缺失概念、信息缺口、信息过时、孤立页面
- 可自动修复项一键批量修复；需人工判断的由 AI 生成修复建议逐条引导
- **健康度量化评分首页实时可见**——作者称同类工具中尚无先例

### 👥 团队协作
- 研究计划、待入库资料、已入库文献、人类产出均支持评论与正文批注
- 人类产出有专属专区，与 AI 生成内容走统一沉淀路径
- 重操作（摄入、体检、探索）全团队可见，避免冲突

### 🔐 数据安全
- admin / editor / viewer 三级角色，写操作全程留痕，操作日志三维审计（动作/操作人/日期）
- 私有化部署：单 Docker 镜像 + SQLite，全部数据在一个 volume
- API Key 本地加密存储

### ⚡ 细节
- 高信息密度工作台：首页仪表盘一屏掌握待审阅、待同步、进行中计划与健康度
- 全局命令面板 Cmd/Ctrl+K；深/浅主题；多格式解析（PDF/Word/Markdown/TXT/HTML）

## 使用注意

- 这是铸造"知识"的平台：**资料需人工审核确认价值后再入库**，避免噪声
- **不适合海量数据**（海量数据用 RAG）；Karpathy 建议 LLM-Wiki 文档控制在 300 篇以内、单篇不超过 1 万字
- 适合垂直领域知识铸造：**不同领域分开建库**

## 战略分析

**1. 与用户现有栈的对照——这是 gbrain 的直接竞品/同类：**

| 维度 | MindForge | gbrain（用户已装） | Obsidian+Hermes |
|---|---|---|---|
| 思想源头 | Karpathy LLM-Wiki | 三代演进（RAG→LLM Wiki→GBrain） | 用户自建体系 |
| 知识结构 | 结构化 Wiki 页（摘要+方法+事实+来源） | 结论摘要+时间线 Markdown | Markdown wiki |
| 图谱 | [[slug]] 双向链接 + 图谱视图（零 LLM） | 向量+图谱混合检索 | wikilink |
| 体检/Lint | ✅ 健康度评分+一键修复 | ✅ 健康检查（orphans/stale/backlinks） | 手动维护 |
| 摄入 | 两阶段（先规划人确认） | capture/ingest skill | kb-archive-article |
| 探索 | 三栏缺口分析+一键研究计划 | gap analysis | - |
| HITL | 贯穿全程 | 部分 | 幕僚长 |
| 部署 | Docker+SQLite 单机 | 本地 PG+Ollama+DeepSeek | 本地 |
| 团队 | 三级角色+批注 | 单用户 | 单用户 |

**结论：MindForge 与 gbrain 是同一思想的两个产品化方向**——MindForge 强在**面向研究的完整闭环**（访谈→计划→缺口→图谱→体检→团队）和**产品化 UI**；gbrain 强在**零 LLM 成本的自动知识图谱 + 43 Skills + 与 Hermes 深度集成**。用户已有 gbrain + Obsidian 体系，MindForge 的产品化功能（健康度评分、研究计划 Agent、引导式访谈）是值得借鉴的 UX 模式，但不需要换系统。

**2. 最值得借鉴的三个模式：**
- **"先规划、人确认后再生成"的两阶段摄入**——与用户刚归档的"轻量化业务应用四步框架"（人留关键节点）、Buzz"手动确认门禁"、TokBrain"预检≠入库"完全同构。这已是多篇独立来源验证的共识模式
- **元数据真实提取注入，杜绝模型编造引用**——作者/arXiv/DOI 从 PDF 提取，不靠模型生成。对 gbrain/归档流程同样适用：事实性字段宁可空着也不让模型编
- **问答反哺知识库**（好答案一键沉淀为 wiki 页）——"越用越聪明"的闭环设计，对应 TencentDB Memory/记忆分层的"经验回流"

**3. 与 LLM-Wiki 思想的一致性：** 300 篇上限、单篇 <1 万字、垂直分库——LLM-Wiki 的边界认知已被多个实现验证（用户 gbrain 的 302 页也在该量级内）。知识库不在大，在结构化连接。
