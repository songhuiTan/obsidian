# 只需 5 步，用 SOLO 实现数据采集到可视化全流程

> 我们用 SOLO（Work 模式）+ 飞书多维表格，搭建了一套"全自动作品采集系统"，支持论坛投稿自动抓取、AI 自动打标签、数据自动写入多维表格。小白也可以跟着复刻。

![封面](../assets/2026-06-04-SOLO数据采集可视化/img_001.jpg)

## 从一个痛点开始

「SOLO X 脉脉挑战赛」的参赛作品通过 TRAE 官方社区发帖提交。随着参与人数增多，赛事运营遇到三个问题：

1. **看不过来**：新作品淹没在海量帖子里
2. **找不到**：想看某个行业或角色的作品翻半天找不全
3. **没数据**：没有可视化的数据大盘

最终这套系统自动采集了 **3400+ 个参赛作品**，一直在稳定运行。

## 5 步搞定全自动作品集

### 第一步：和 SOLO 聊需求

选择 **Work 模式**（适合非代码工作，AI 可直接操作文件、浏览器、飞书）：

```
/plan "论坛作品地址" 通过飞书多维表格定时更新获取链接论坛作品信息，写入多维表格
```

SOLO 梳理出需求：
- **自动采集**：从 TRAE 论坛自动获取参赛作品帖
- **智能分析**：AI 自动提取行业、职业、技能类型等标签
- **多维展示**：同步到飞书多维表格，支持筛选、排序、统计
- **全自动化**：定时任务自动同步，无需人工干预

补充需求：每个作品采集标题、作者、链接、浏览数、回复数、投票数、发帖时间；AI 分析出行业、职业、Skill类型、Skill名称、Skill简介、Skill链接。最终形成 **14 个字段**。

> **💡 小贴士**：与 SOLO 对话时需求越具体越好，不要说"帮我做个采集工具"，要说"帮我采集论坛帖子，字段包括 XXX、YYY，同步到飞书表格"。

### 第二步：配置飞书应用

#### 2.1 创建飞书应用
打开飞书开放平台 → 创建应用 → 选择自建应用 → 填写名称 → 上传图标。

#### 2.2 获取凭证
在应用详情页「凭证与基础信息」获取 **App ID** 和 **App Secret**。

#### 2.3 开通权限
在「权限管理」中开通以下权限：

```
base:app:update, base:field:read, base:form:update, base:history:read,
base:record:create, base:record:delete, base:record:read,
base:record:retrieve, base:record:update, base:table:read,
base:table:update, bitable:app, bitable:app:readonly, im:resource
```

#### 2.4 发布应用
「版本管理与发布」→「创建版本」→「申请发布」。⚠️ 发布后才能调用 API。

#### 2.5 获取多维表格信息
从 URL 中提取：`/base/` 后的是 **App Token**，`table=` 后的是 **Table ID**。

### 第三步：飞书多维表格配置

#### 3.1 字段配置
字段名和格式必须与采集字段对应，否则传输错误。

#### 3.2 添加应用
在多维表格中添加上面发布的飞书应用，实现数据写入。

### 第四步：用 SOLO 开发采集服务

#### 4.1 一句话完成开发

```
根据以上plan最终规划方案，执行项目代码开发，实现论坛数据采集和飞书多维表格同步。
```

SOLO 自动生成完整项目结构：

```
forum-crawler/
├── config.py           # 配置文件
├── feishu_client.py    # 飞书API客户端
├── forum_crawler.py    # 论坛数据采集
├── ai_analyzer.py      # AI智能分析
├── sync.py             # 增量同步逻辑
├── main.py             # 主入口
├── .env                # 环境变量
└── requirements.txt    # 依赖包
```

#### 4.2 各模块作用

**config.py + .env**：config.py 通过 `os.getenv()` 读取 .env 中的敏感信息（飞书凭证、AI API Key），实现配置与密钥分离。

**feishu_client.py**：飞书 API 封装，核心操作：获取 access_token、清空表格（逐行更新需半小时，清空批量写入只需1分钟）、批量创建记录（每次最多500条，超限分批，失败时指数退避重试）。

**forum_crawler.py**：基于论坛的 JSON API（Discourse 开发）分页获取帖子，提取标题、作者、浏览数、回复数等。

**ai_analyzer.py**：对每个帖子调用 AI API 提取结构化标签（行业、职业、技能类型等），通过明确的分类选项约束 AI 输出范围。

**sync.py（增量同步机制）**：

```
1. 获取论坛所有帖子
2. 计算每个帖子的内容指纹 MD5(title + excerpt)
3. 与本地缓存比对：
   - 指纹相同 → 跳过
   - 指纹不同 → 重新AI分析
   - 新帖子 → AI分析 + 写入缓存
4. 将需要更新的记录写入飞书
```

缓存存储在 `ai_cache.json` 中，避免每次都全量调用 AI API。

### 第五步：部署到服务器

#### 5.1 环境准备

```bash
sudo apt update && sudo apt install python3 python3-pip -y
pip3 install requests python-dotenv --break-system-packages
```

#### 5.2 上传项目文件

```bash
# 方法1：scp
scp -r forum-crawler/ root@你的服务器IP:/opt/forum-crawler/

# 方法2：git
git clone 你的仓库地址 /opt/forum-crawler
```

#### 5.3 配置环境变量

在服务器创建 `.env` 文件，填入飞书 App ID/Secret 和 AI API Key。

#### 5.4 首次运行测试

```bash
cd /opt/forum-crawler && python3 main.py
```

检查：论坛数据采集成功、AI 分析正常返回、飞书表格写入成功。

#### 5.5 设置定时任务

```bash
crontab -e
0 * * * * cd /opt/forum-crawler && /usr/bin/python3 main.py >> logs/cron.log 2>&1
```

## 最终成果

- **3400+** 参赛作品自动采集
- **14 个** 字段的结构化数据
- 每 **小时** 自动同步更新
- AI 智能标签提取（行业、职业、技能类型）
- 增量同步，只处理新增和变更内容
- **7×24 小时** 自动运行，无需人工干预

## 踩坑实录

| 问题 | 现象 | 解决 |
| --- | --- | --- |
| **字段名称不一致** | 写入飞书报错 FieldNameNotFound | 统一使用中文字段名，保持完全一致 |
| **字段格式不一致** | 写入超链接字段报错 | 使用 `{"link": "url", "text": "显示文本"}` 格式 |
| **资源规划不合理** | 每次同步都调用 AI，API 费用高 | 增量分析，只对新增或变更的帖子调用 AI |
| **Rate Limit 限流** | 请求频率过高被飞书 API 限流 | 指数退避重试 + 请求间增加延迟 |
| **全量同步效率低** | 3400+ 帖子处理时间很长 | 增量同步 + 分页获取 + 只处理变更数据 |

## 核心经验

1. **先梳理需求，再动手开发** — 和 SOLO 对话时把需求说清楚
2. **飞书配置是第一步** — 先创建应用、开通权限，再写代码
3. **增量思维** — 不要每次全量处理，用缓存和指纹比对
4. **错误处理要完善** — API 调用会失败，必须有重试和日志
5. **先本地测试，再部署服务器** — 确保本地跑通再上传
