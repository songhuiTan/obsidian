# AI智能批改作业系统 — 程序员小孟

> **核心摘要：** 一款面向学校的AI智能批改系统，覆盖从试卷上传、文档解析、AI批改到成绩发布的全流程。支持全学科（语数英物化等），可对接云端API或本地私有化大模型部署，支持客观题规则评分 + 主观题大模型评分双引擎。

---

## 系统解决的问题

1. 降低教师重复性批改工作量
2. 提高主观题评分的一致性和可追溯性
3. 将错题转化为知识点、能力项和教学改进数据
4. 根据学生薄弱环节自动生成个性化练习或新试卷
5. 通过权限、日志、模型版本和评分证据保证结果可审计
6. 支持云端 API、国产模型及本地私有化模型灵活切换

## 部署方案

- **本地部署：** 硬件配置要求高（显卡贵），费用约10万
- **云端部署：** 按token付费，适合使用量不大的场景

## 系统功能需求

### 🏫 2.1 教学基础数据

| 功能 | 详细要求 | 优先级 |
| --- | --- | --- |
| 机构管理 | 支持集团、学校、校区多级组织；租户间数据隔离 | P0 |
| 学年学期 | 配置学年、学期、考试周期和教学周 | P0 |
| 年级班级 | 建立年级、班级、行政班和教学班 | P0 |
| 学科课程 | 配置学科、教材版本、章节和知识点体系 | P0 |
| 师生管理 | 单个新增、Excel 批量导入、接口同步、停用与转班 | P0 |
| 教师任课关系 | 绑定教师、学科、班级和有效时间 | P0 |
| 学号匹配 | 支持学号、姓名、二维码、条形码、答题卡编号识别 | P0 |

### 📥 2.2 试卷、题目与作业上传

**上传方式：** PDF、DOCX、图片；批量压缩包；移动端自动裁边/透视矫正/去阴影；第三方导入（教务系统、学习平台、网盘等）；在线创建（富文本、公式、表格、音频占位、评分量规）

**文档解析流水线：**
1. 文件安全检查、病毒扫描和格式标准化
2. 页面方向识别、旋转、去噪、裁边、透视矫正
3. 页眉页脚、题号、分值、答题区域和图片区域识别
4. 题目切分及大题/小题/材料题从属关系识别
5. 印刷体、手写体、数学公式、表格和图形区域分类
6. 提取题干、选项、标准答案、解析、知识点、难度和分值
7. 形成可人工校正的结构化试卷

**质量校验：** 识别不清/缺页/重复页/倒置页告警 → 题号断档/分值异常/标准答案缺失拦截 → 去重提示 → 三栏预览（原图—识别文本—题目结构）

### 🗂️ 2.3 题库与评分标准

- 题目支持：版本管理、标签、来源、学科/年级/教材/章节、知识点、能力层级、难度、题型、预计用时
- 评分量规（Rubric）：得分点名称 → 分值 → 满分/部分得分/常见错误 → 互斥或依赖规则 → 示例答案与反例
- 数学题：数值容差、单位换算、等价表达式、步骤分
- 作文：立意、结构、内容、语言、规范、创新等多维度

### 🤖 2.5 一键 AI 批改

**批改流水线（10步）：**
1. 答卷质量检查
2. 学生身份与试卷版本识别
3. 题目区域定位
4. OCR、手写与公式识别
5. 客观题规则评分
6. 主观题大模型评分
7. 得分点校验、总分校验和异常检测
8. 多模型复核或第二次独立评分
9. 生成评分证据、评语和置信度
10. 自动通过或进入人工复核队列

**评分结果保存：** 原图 → OCR结果 → 标准答案/Rubric版本 → 得分点命中 → AI建议分/最终分/置信度 → 模型供应商/ID/提示词版本 → 修改人/修改记录

### 🎛️ 2.6 模型选择与路由

支持按考试配置模型或系统自动路由，维度包括：
- OCR模型、通用文本模型、视觉理解模型、数学/推理模型、作文评分模型
- 主评模型和复核模型
- 温度、推理强度、超时、重试、最大输出
- 单题成本上限、整场预算、每日额度
- 数据是否允许发送至外部 API

### 👩‍🏫 2.7 手动批改

- 四种模式：按学生、按题目、按班级、按阅卷任务
- 同屏展示：原图 + 识别文本 + 标准答案 + Rubric + AI评分证据
- 修改AI分数需选原因（识别错误/标准答案问题/评分偏严/偏松/特殊作答/其他）
- 支持双评、三评和仲裁机制

## 三、技术方案

| 层 | 推荐 |
| --- | --- |
| 前端 | Vue 3 + TypeScript + Vite + Element Plus/Naive UI |
| 标注画布 | Fabric.js 或 Konva.js |
| 后端业务 | Java 21 + Spring Boot 3 |
| AI 服务 | Python 3.12 + FastAPI + Pydantic |
| 工作流编排 | Temporal、Camunda 或自建状态机 |
| 数据库 | PostgreSQL 16+ |
| 缓存 | Redis Cluster |
| 消息队列 | Kafka（大规模）或 RabbitMQ（中小规模） |
| 对象存储 | S3、MinIO 或云对象存储 |
| 向量检索 | pgvector → Milvus |
| 分析型数据库 | ClickHouse |
| 搜索 | OpenSearch/Elasticsearch |
| 容器 | Docker + Kubernetes |
| 推理框架 | vLLM/SGLang，OCR 可独立 Triton 服务化 |
| 可观测性 | OpenTelemetry + Prometheus + Grafana + Loki |
| CI/CD | GitLab CI、GitHub Actions 或 Jenkins |
