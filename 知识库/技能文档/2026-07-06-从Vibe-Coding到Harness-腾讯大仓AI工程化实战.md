## Harness 六大资产

### 1. Rule（规则）→ 能判定就下沉为脚本
**天然天花板：自然语言可被解释性执行。** AI 总能找到理由绕过规则（"这条规则场景特殊"、"这是历史问题"）。所以几乎所有可判定的约束都下沉为 Skill 或脚本，独立 Rule 最少。

### 2. Skill（标准操作手册）→ 注意力管理
当前 11 个 Skill，分四组：
- **脚手架与代码规范**（4个）：协议与领域模型、数据访问层 GORM 规约、服务层规范、HTTP 处理层规范
- **测试规范**（2个）：单元测试 mock 约定、接口测试生成
- **需求理解**（3个）：PRD 完整性自评（5维评分 0~100）、影响半径分析、PRD 模板
- **代码审查**（2个）：范围溢出检查、前端增量与视觉审查

本质：**把"这件事具体怎么做"从主 prompt 拆出去，让主 Agent 注意力只放在当前认知任务上。**

### 3. Sub Agent → 只留 4 个
| 角色 | 职责 | 不允许 |
|------|------|--------|
| **需求 Agent** | TAPD→需求理解+影响半径分析 | 不许写技术方案 |
| **方案 Agent** | 需求→可执行技术方案+任务清单 | 不许改需求理解文档 |
| **开发 Agent** | 按设计落代码+接口测试产物 | 不许超出设计范围 |
| **代码审查 Agent** | 4 维度收口 | 不许改代码，只能提阻塞项 |

**核心纪律：下游 Agent 不可直接修改上游产物，只能提阻塞项，由总控 Agent 打回上一棒。**

**判断标准：能用 Skill 解决的就不开新 Agent**（Agent 有状态/turn/token 成本，Skill 是无状态文档加载）；**能写成 bash 的就不让 Agent 跑**（确定性工作下沉为脚本）。

### 4. Workflow → 13 阶段接力赛
```
初始化 → 需求分析 → 需求确认 → [Bug复现] → 技术方案 → [方案确认]
→ 方案评审 → 分支准备 → 开发 → 集成测试 → 代码审查 → 验收 → 交付收尾
```
**阶段拆分的两条标准**：①有独立失败模式？②失败时回退位置不同？两个"是"才独立。

**关键教训**：集成测试从"后置"（代码审查之后）挪到"前置"（代码审查之前），代码审查打回次数从 1.8→0.4。Bug 复现从"必走"改为条件触发。

### 5. 7 道门禁脚本 → 把"完成"的定义权拿回来
| 阶段 | 门禁 | 类型 |
|------|------|------|
| 开发完成 | 覆盖率检查（全量≥40%+增量≥85%） | 软门禁 |
| 开发完成 | 制品一致性检查 | 软门禁 |
| 开发完成 | 静态检查+安全扫描（golangci-lint 12检查器） | **硬门禁** |
| 集成测试 | 沙箱部署（make sandbox + 网关健康） | **硬门禁** |
| 集成测试 | 接口测试（真实 HTTP） | **硬门禁** |
| 集成测试 | 前端冒烟（Playwright） | 软门禁 |
| 验收 | 日志验收 | 软门禁 |

**反作弊设计——基线对比**：开发前先跑基线快照(A)，开发后跑当前状态(B)，只阻塞 **B - A**（新增的失败），防止 AI 用"历史问题"糊弄。

**原则**：硬门禁宁少不多，流程频繁打断会让团队退回 Vibe Coding。

### 6. 5 个 MCP → 交付闭环
TAPD / iWiki / 工蜂 / Knot / 企微。补完"从开发闭环到交付闭环"的最后一段路。

## 半自动模式（5 个人工关卡）

| 关卡 | 耗时 | 频率 |
|------|------|------|
| 需求确认 | 10~30秒 | 每需求1次 |
| 方案确认 | 30~60秒 | ~40%需求 |
| 方案评审打回 | 1~2分钟 | <10% |
| 前端冒烟选择 | 5秒 | 涉及前端时 |
| 熔断暂停 | 越短越好 | 异常情况（连续打回≥3次） |

**硬约束：不能让用户每分钟点一次以上。** 每个人工关卡设计三级兜底：UI 按钮 → 文本关键词 → 语义识别。

## 关键结论

1. **PRD不能被信任 → 影响半径分析**
2. **方案对不上代码 → 代码审查查方案一致性**
3. **改完没人验证 → 7道门禁（脚本判定≠AI汇报）**
4. **交付碎片化 → 5个MCP打通全链路**
5. **模型够强了，工程没跟上**——四件事没有一件是模型问题，都是协作/流程/信任问题
6. **Harness 主要不是给 AI 用的，是给团队用的**——目标不是让 AI 更聪明，而是稳定/规范/可审计
7. **Spec-first**：先磨 SPEC 达成共识，再落地
