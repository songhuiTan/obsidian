## 文章概要

讨论 AI Agent 自演进的底层工程体系。核心判断：Agent 的"越用越强"不是技术奇迹，而是**两套闭环（运行闭环 + 训练闭环）相互喂养形成飞轮**。引用 NVIDIA 7月1日技术博客（RLVR/GRPO/Verifier），但更强调从更轻量的数据回流模式启动。

---

## 两套闭环

### 运行闭环（记录发生了什么）
用户提问 → 理解意图 → 调用检索/工具 → 生成结果 → 用户反馈 → 日志沉淀

### 训练闭环（把记录变成能力提升）
失败/高质量样本 → 自动构造成 QA 对 → 评测集更新 → 轻量微调或策略优化 → 验证通过 → 新版本上线

> 只有运行没有训练 → "会记笔记但不复习的学生"  
> 两者相互喂养 → 形成飞轮

---

## NVIDIA 的高阶路线

NVIDIA 7月1日技术博客核心观点：

- **Prompt/RAG/工具链能解决的问题有限** — 反复犯同样的工具调用错误、长流程迷失，需要训练信号
- **强化学习把"任务成功"变成训练信号** — 让模型自己试，做对加分做错减分
- **Agent RL 需要"环境"** — 能执行动作、返回反馈的沙箱/校验器

### 关键概念

| 概念 | 说明 |
|:---|:---|
| **RLVR** | 用可客观验证的奖励训练（代码跑通、JSON 格式对），比人类打分更便宜可扩展 |
| **GRPO** | 同一问题生成多个回答互相比较，不需要额外价值模型，Agent RL 主流起点 |
| **Verifier** | 判断输出"对不对"的程序（JSON校验/单元测试/模拟器），质量直接决定 RL 效果 |

NVIDIA 7 步实操：选行为 → 跑基线评测 → 判断是否需要 SFT → 构建验证器 → 跑小 GRPO → 跟踪指标 → 检查失败并谨慎上线。

## 更落地的飞轮模式

### 冷启动
文档入库 → 自动分片向量化 → 自动生成 QA 对 → 首次轻量微调上线

### 运行中积累
用户提问 → 多路检索 → 融合排序 → LLM 生成 → 用户反馈（点赞/点踩 + 失败类型标签）→ 保留完整请求/上下文/检索结果

### 数据回流
反馈数据质量筛选 → 自动构造新训练样本 → 定期轻量微调（LoRA）→ 评估通过上线 → 标注数据同步反哺检索策略

---

## 现在可以做的 5 件事

1. **日志能力** — 记录完整上下文、工具调用、检索内容、中间步骤、最终结果、用户反馈
2. **反馈能力** — 点赞/点踩 + 失败类型标签（检索错/格式错/工具错/推理错），支撑自动分类和样本构造
3. **样本能力** — 自动/半自动的失败样本→训练样本构造流程
4. **评测能力** — 每次改 Prompt/检索/模型/工具都跑评测，评测集从真实失败持续补充
5. **更新能力** — LoRA 轻量方法建立"发现问题→构造样本→优化→评测→上线"循环

---

## 关键警告

- **不要期待 Agent "自动进化"** — 飞轮需要人设计日志结构、定义反馈标签、维护评测集、执行微调
- **强化学习不是银弹** — 适合"成功可被程序验证"的场景（代码生成/工具调用/格式校验）
- **先从最轻的优化开始** — Prompt 能解决不要急着微调
- **数据质量比训练方法重要** — 日志不完整/反馈标签混乱，再好的算法也救不了

> 你在"越用越被修"，还是在"越用越强"？前者靠人盯，后者靠飞轮。
