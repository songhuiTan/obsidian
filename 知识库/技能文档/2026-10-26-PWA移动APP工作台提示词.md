# PWA 移动 APP 工作台提示词

> 一份可复用的两段式提示词：**第一段给通用 PWA 工作台硬性约束（8 条）**，**第二段给具体岗位工作台的风格/布局/模块描述**。换岗位时只改第二段，第一段的工程要求保持不动——这是这套提示词最关键的结构设计。

## 一、通用约束提示词（模板，8 条硬性要求）

```text
帮我搭建一个***岗位的工作台，包括***日常工作，html版本的，同时还要符合以下要求：
```

1. **PWA 全屏桌面应用**
   要做成 PWA 的风格，Android 手机和 iPhone 都能添加成桌面快捷方式，而且打开要是全屏的（无浏览器地址栏），其中移动端要变成底部导航。
2. **多设备云剪贴板同步**
   资料库增加一个全部 JSON 直接一键复制出来和写入的功能，方便我通过云剪贴板（微信/备忘录）来实现多设备数据同步。
3. **桌面专属 App 图标**
   存为 PWA / 添加到主屏幕时，必须自带专属高清 App 图标。
4. **移动端克制收纳数据入口**
   资料库底层数据表格在移动端也要加上，但要放得隐蔽一些；包括导出 JSON、导入这些功能在移动端不要堆在最上面。
5. **检查在线版本更新**
   移动端增加一个检查更新的功能，如果网址对应的 HTML 更新了，能防缓存检测并更新，同时不丢失本地已记数据。
6. **手机端长文字排版优化**
   对手机端单独优化，不要出现一行文字过长但又有多个元素挤在一起变形的情况。
7. **导出标准 manifest.json 文件**
   同步生成 manifest.json，支持一键导出标准的 manifest.json 实体文件，方便在独立服务器或各种安卓浏览器环境下部署与安装。
8. **PC 端独立桌面系统**
   在 PC 电脑端的谷歌浏览器（Chrome）上也能创建桌面快捷方式，能全屏 / 作为独立窗口打开，像本地安装的独立管理系统一样运行。

## 二、具体岗位提示词示例：小学教师工作台

```text
做一个「小学教师工作台」单文件 HTML（Tailwind CDN + 内联 CSS/JS，无框架、无后端）。

风格：米杏底色 #F6F4F0 的纸质温暖感，卡片纯白 + rounded-3xl + 极轻阴影；标题用衬线体（Noto Serif SC），正文用无衬线。
主色可用 CSS 变量切换，默认深松绿 #27473E，另备紫梅 / 杏木 / 霁蓝三套。

布局：桌面左侧常驻侧边栏（品牌 + 分组导航 + 底部存储状态卡），移动端收成抽屉 + 底部 5 Tab。
主区顶部一行日期与"已实时存储"，大标题「今天，静待花开」，右侧放主题切换 / 全屏 / 云剪贴板 / 资料库备份。

首页四块：
① 左边一张深色大卡（主色底，含装饰圆环），显示"班级专注指数 88/100"+ 描述 + "记录教学微心得"按钮；
② 右边 2×2 四宫格彩色快捷入口：奖小红花 / 排课程·待办 / 家校留言 / 评语快抄；
③ 三列白卡统计：今日课时 3 节、作业批改 42/48、重点关怀 2 人；
④「班级轮值今日」+「讲台随手贴 textarea」+「待办清单」。

另建 6 个视图：学生与红花榜、课堂工具箱（随机点名 + 倒计时）、课表与作业簿、班务与值日排班、家校联系、资料库与云剪贴板。

数据全部存 localStorage 并即时保存，配 PWA 安装能力。文案要温和有书卷气，不要网络梗。
```

## 三、提示词的工程要点拆解

### 为什么这样写

| 设计 | 作用 |
|------|------|
| **两段式：通用约束 + 岗位描述** | 通用段是资产（PWA/存储/更新/排版），岗位段是一次性消耗品。换岗位只改第二段，避免每次重新描述工程细节 |
| **单文件 HTML + CDN，无框架无后端** | 直接把 html 文件丢服务器/静态托管就能用，手机扫码即装，零运维 |
| **localStorage + 即时保存** | 无后端意味着数据只在本地；配合第 2 条云剪贴板 JSON 导出，用「复制 → 微信/备忘录 → 另一台设备粘贴导入」实现穷人版多端同步 |
| **移动端入口"克制收纳"** | 数据表格/导入导出是低频高危操作，放显眼位置会误触；要求"隐蔽一些"是为了让日常主流程干净 |
| **防缓存检查更新** | 静态 HTML 最大的坑是手机 PWA 缓存旧版；显式要求版本检测 + 本地数据不丢，等于要求「缓存失效 + 数据迁移」两件事一起做 |
| **PC 端独立窗口** | Chrome「创建快捷方式 → 在窗口中打开」可得到无地址栏的独立窗口，等于在 Windows/macOS 上也有一份"客户端" |

### 提示词里隐含的技术规格（可核对实现是否达标）

- **PWA 全屏**：`display: "standalone"` 或 `"fullscreen"`；iOS 还需 `apple-mobile-web-app-capable` + `apple-mobile-web-app-status-bar-style`，但 iOS 不读 manifest 的部分字段，需要 meta 兜底
- **专属图标**：`icons` 数组至少 192×192 与 512×512，最好加 `maskable`；图标可用内联 SVG/data URI 生成，避免外链丢失
- **manifest.json 实体导出**：把运行时 manifest 对象 `JSON.stringify` 成 Blob 下载；单文件场景通常用 JS 动态注入 `<link rel="manifest">`，导出功能是给"搬去独立服务器部署"用的
- **防缓存更新**：常见做法是 `version.json` / HTML 内嵌版本号 + `fetch(..., {cache:'no-store'})` 比对，或 Service Worker 的 `skipWaiting` + `clients.claim`；关键是更新前先把 localStorage 快照备份，再 reload
- **移动端底部导航**：移动端用 `position: fixed` 底栏 + `env(safe-area-inset-bottom)` 适配 iPhone 刘海屏，桌面侧边栏用媒体查询在 <768px 时折叠成抽屉

### 复用扩展方向

- 换岗位只需替换第二段：销售工作台、客服工作台、班主任工作台、个人运营工作台
- 数据量涨到 localStorage 吃紧时，把 JSON 导出/导入接成 WebDAV 或 Supabase，第一段约束不变
- 需要多人协作才需要后端；单人工位用「单文件 + 云剪贴板」是最低成本可行的方案
