## 概述

SkillCorpus 是一个针对大规模开源社区 Skill 文档的筛选与质检框架。从 GitHub 等平台爬取 **82 万份** SKILL.md 格式文件，经过六阶段流水线清洗、去重、安全质检与分类评级，最终沉淀出 **96,401 份** 合规、高质量、可商用的标准化 Skill，并配套专门的检索推荐系统。

论文还设计了三套测试集（407 个真实任务），在两个独立 Agent 框架（OpenClaw 和 Raven）上验证效果。实验结论：搭载 SkillCorpus 后全部测试集性能稳定正向提升，没有出现整体变差的情况。

## 六阶段过滤流水线

| 阶段 | 动作 | 淘汰比例 |
|------|------|---------|
| ① 结构与格式 | 检查标准 SKILL.md 格式、内容长度 | 剔除太短/太长的 |
| ② 内容校验 | 格式规范检查 | — |
| ③ 去重 | 精确匹配 → 语义匹配 → LLM 最终判定 | 干掉 ~64%（82万中近60%是重复的） |
| ④ 质量打分 | AI 裁判三围打分：实用性/鲁棒性/安全性 | 按分数筛选 |
| ⑤ 安全与授权 | 5 条硬性安全规则（命令注入/提示词注入/危险执行/权限绕过/违法内容），只保留 MIT/Apache 2.0 等许可 | 触犯规则直接淘汰 |
| ⑥ 归类入库 | 打标签 + 生成向量 | 最终 96,401 份 |

### 三维质量打分

| 维度 | 考察内容 |
|------|---------|
| **实用性 (Utility)** | Skill 描述是否清晰？能解决什么问题？何时该用/不该用？ |
| **鲁棒性 (Robustness)** | 内容是否靠谱？步骤描述准确？有无矛盾或语法错误？ |
| **安全性 (Safety)** | 是否危险？有无诱导注入恶意指令、泄露密钥、执行危险操作？ |

## 检索与推荐系统（金牌导购）

三层递进：

1. **粗筛**：任务描述 → 快速捞几百个候选 Skill
2. **精排**：精细排序模型打分排序，挑出最靠前的几十个
3. **LLM 精准筛选器**：通读完整 Skill 全文，返回 0-2 条真正适配的 Skill（避免上下文塞满无关内容）；附带任务语句改写（行业黑话 → Skill 库通用词汇），找不到匹配时判定无需调用工具

## 实验验证

### 三套测试集 × 两套框架 × 大小模型

| 测试集 | 裸模型基线 | 搭载 SkillCorpus | 提升 |
|--------|-----------|-----------------|------|
| SkillsBench（407任务） | — | — | **平均 +7.5pp** |
| SkillsBench + Raven + 397B 模型 | — | — | **+13.4pp** |
| SkillsBench + Claude Opus | — | — | **+8%** |
| QwenClawBench | — | — | **平均 +2.79 分** |
| GDPVal（高基线 65%-85%） | — | — | **+1.51 分**（天花板效应） |

### 关键发现一：Harness 差距巨大

两套框架使用完全相同的 Skill 库，提升效果天差地别：

| 框架 | 执行逻辑 | Skill 效果 |
|------|---------|-----------|
| **Raven** | 完整执行「推理→运行脚本→校验结果→修正错误」闭环 | Skill 操作步骤能完整落地，涨幅高 |
| **OpenClaw** | 经常写完代码就终止流程，不执行、不校验 | Skill 内容无法发挥价值，涨幅低 |

> 注：财报、文案等只看文字输出、不需要运行代码校验的任务，两套框架差距消失。

### 关键发现二：Skill 覆盖度决定涨幅

| 匹配程度 | 平均提升 |
|---------|---------|
| 匹配分低（库里无对应 Skill） | 平均 +2.2% |
| 匹配分中等 | 平均 +6.2% |
| 匹配分高（完美适配流程） | **平均 +25.1%** |

## 典型场景：什么时候有用 vs 翻车

### ✅ 成功案例：工业故障标准化

设备日志自由文本 → 标准化内部故障代码。无 Skill 时模型硬编码关键词，准确率仅 66.2%（要求 70%+）。匹配到专门描述此流程的 Skill（多证据加权评分、站台兼容性过滤、置信度校准）后准确率达标，任务通过。

### ❌ 失败案例：PPT 内嵌 Excel 修改

修改 PPT 文件里内嵌 Excel 表格的汇率数字。无 Skill 时 AI 自己摸索解开 PPTX → OLE → ZIP → XML，8 项全过。有 Skill 时检索到通用"操作 Excel"和"操作 PPT"的 Skill，按流程尝试打开独立文件失败，只过 6 项。

**核心启示：Skill 流程必须和任务底层逻辑完全匹配。** 仅主题相关但流程不匹配的 Skill 会限制模型自主创新，反而降低效果。质量分数无法预判单任务成败——流程适配度才是核心。

## 战略分析

### 与现有体系的对照

SkillCorpus 的六阶段流水线和三层检索系统，与当前 Hermes/OpenClaw 生态的 Skill 体系有直接交叉：

| 维度 | SkillCorpus | Hermes 当前体系 |
|------|------------|---------------|
| Skill 来源 | GitHub 社区爬取（82万原始 → 9.6万合格） | 社区 Skill Hub + 用户自建 |
| 质量把关 | AI 三围打分（实用/鲁棒/安全）+ 硬性安全规则 | SKILL.md 格式规范，无自动质检 |
| 去重 | 精确+语义+LLM 三重去重（~64% 重复） | 无去重机制 |
| 检索 | 粗筛+精排+LLM 三层递进 | 命名+关键词匹配 |
| 框架测试 | Raven（完整闭环）vs OpenClaw（不执行不校验） | Hermes + skill_view 加载 |
| 安全规则 | 5 条硬性规则（命令注入/提示词注入/危险执行/权限绕过/违法内容） | 无内置安全扫描 |

### 高价值启示

1. **Harness 执行闭环是 Skill 价值兑现的关键**。实验数据证明：同样一份 Skill，在 Raven（完整执行）上比 OpenClaw（写完不执行）效果好几倍。这个结论直接指向当前 Hermes Skill 体系——如果 Skill 只是"被加载"但不保证"被完整执行"，再好的 Skill 也不会产生实际效果。**Skill 的价值不在定义，在执行闭环。**

2. **流程适配度 > Skill 质量分**。一个高分但流程不匹配的通用 Skill 反而会拖累任务（PPT 内嵌 Excel 案例）。这提示：检索系统需要关注"当前任务的具体执行路径"而非仅"主题关键词"。

3. **安全质检自动化**。Hermes Skill Hub 目前缺少自动安全扫描。SkillCorpus 的 5 条硬性规则（命令注入/提示词注入/危险执行/权限绕过/违法内容）是直接可参考的安全基线。

4. **中文 Skill 库的空白**。论文明确标注"中文适配性未知"。当前中文社区（废才俱乐部等）积累的 Skill 正在形成自己的体系，如果未来有中文 Skill 质检框架，会是差异化机会。

### 能力差距

- Hermes 当前 Skill 缺少：自动去重、质量评分、安全扫描、智能检索
- 但 Hermes 的优势是：与 Obsidian 知识库结合、与 TencentDB Memory 结合、二次开发灵活
- 最值得直接借鉴的：**安全规则基线**（5 条硬性规则）和 **三层检索漏斗**（粗筛→精排→LLM 精选）
