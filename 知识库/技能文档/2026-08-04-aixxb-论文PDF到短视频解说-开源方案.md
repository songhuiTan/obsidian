## 概述

一个把论文 PDF 自动变成**短视频解说**的完全开源工具：上传 PDF 或填入 arXiv/PDF 直链，系统自动完成论文解析、图表提取、关键证据筛选、分镜生成、中/英口播和 720P 视频合成。

**关键特性：整条链路的关键推理都在本机完成**，不依赖 DashScope、OpenAI 或其他远程推理 API。用本地 Qwen3.5-9B 理解论文 + 本地 MegaTTS3 生成口播。

## 八步流程

```
PDF/URL
 ↓
下载、校验、页面渲染
 ↓
正文抽取 + Figure/Table caption 定位
 ↓
Qwen 论文摘要、图表框选、关键证据筛选
 ↓
故事线、总结卡、贡献卡、分镜和质量门禁
 ↓
释放 Qwen 显存
 ↓
MegaTTS3 逐镜口播 + 时长校正
 ↓
画面、音频、字幕封装为 MP4 + SRT
```

## 核心能力

| 阶段 | 说明 |
|------|------|
| 论文解析 | 提取正文、页码、Figure/Table 标题和页面图片 |
| 论文理解 | 本地 Qwen3.5-9B：问题、方法、贡献、证据、限制、结论 |
| 图表提取 | 综合 caption、版面边界和视觉模型结果，裁出有信息量的图表；去重相同 caption |
| 叙事生成 | 总结卡、贡献卡、方法图、实验结果和结论卡 |
| 质量门禁 | 自动检查镜头编号、重复素材、句子完整性、时长和 TTS 文本 |
| 口播 | 卸载 Qwen 再加载 MegaTTS3，避免两套模型抢显存 |
| 合成 | ffmpeg 合成 1280×720、24FPS MP4 + 完整 SRT 字幕 |

**字幕与口播双文本设计**：字幕保留论文原始术语，TTS 文本针对"三维、RoPE、VGGT"等技术词做读音归一化——不牺牲专业表达，也减少机器口播读错。

## 中间产物（可排查）

```
runs/YYYYMMDD_HHMMSS_论文名/
├── source/                    # 输入 PDF
├── pages/                     # 渲染后的页面
├── figures/metadata.json      # 图表编号、caption 和裁剪边界
├── cards/                     # 开场、贡献和结论卡
├── paper_brief.json           # 结构化论文摘要
├── selected_assets.json       # 最终视觉素材顺序
├── script.json                # 完整分镜、字幕和口播
├── audio/                     # 分段 WAV
├── paper_explainer.srt        # 字幕
└── paper_explainer.mp4        # 最终视频
```

排查顺序：`paper_brief.json → metadata.json → selected_assets.json → script.json → SRT → MP4`，不用反复重跑整条任务。

## 部署（ModelScope 创空间 / GPU Workspace）

**创空间：** Gradio SDK，入口 `app.py`。建议单卡 ≥16 GiB 显存、32 GiB 内存、35 GiB 磁盘（两套模型约 22-23 GiB）。不要用 Gunicorn/Uvicorn 多 worker，队列单任务并发，Qwen 和 MegaTTS3 严格分阶段加载释放。

```bash
# 模型下载
python scripts/check_environment.py
python scripts/download_models.py --model all --workers 8
# 模型保存到 models/Qwen3.5-9B 和 models/MegaTTS3

# 启动
python app.py  # 默认 7860

# 命令行批处理
python demo.py --pdf /mnt/workspace/data/paper.pdf --duration 180 --language 中文
```

## 隐私与成本边界

- 模型下载完成后，上传本地 PDF 全流程**可断网运行**；URL 输入仅下载论文需要网络
- 所有产物写入本地 `runs/`，不自动上传第三方推理服务
- GPU 创空间按运行时长/实例规格计费，建议空闲停止实例
- 首次加载模型、复杂论文图表检测、CPU 视频编码都需要时间

## 战略分析

### 与现有体系的对照

| 维度 | 本项目 | 知识库已有论文工具 |
|------|--------|------------------|
| 输入 | 论文 PDF / arXiv 直链 | Paper2Any（论文拆 PPT/架构图/海报） |
| 输出 | 短视频解说 + SRT | 可编辑文档 |
| 模型 | 本地 Qwen3.5-9B + MegaTTS3 | 依赖远程 API 居多 |
| 推理 | 全本地，断网可用 | 混合 |
| 部署 | ModelScope 创空间 / GPU Workspace | — |
| 中间产物 | 8 类 JSON/素材可排查 | — |

### 高价值洞察

1. **全本地推理是差异化**：Qwen3.5-9B 理解 + MegaTTS3 口播，断网可跑。对隐私敏感场景（企业内网论文分析）和成本控制（不按 token 付费）有价值。

2. **"可检查的中间产物"是工程化的关键**：不是黑盒"总结一下"，而是把任务拆成可定位的阶段（解析/选图/分镜/口播/封装），每个阶段留 JSON——"视频看起来不对"能定位是摘要错、选图错还是 TTS 读音错。这和 rgraph 的 JSONL 事件存储、Trellis 的 workspace journal 是同一条工程主线。

3. **双文本（字幕 vs TTS）设计巧妙**：字幕保留"RoPE"等原始术语，口播读"三维、RoPE"归一化发音——解决专业内容 TTS 的常见痛点。

4. **与视频工具链互补**：知识库已有 z-video-downloader（下载）、claude-video（视频理解）、echocut（视频剪辑）；本项目补上"内容生成"环节——论文 → 解说视频。如果 Hermes 需要"读论文出视频"能力，这个工作流是参考实现。

### 局限

- 需要 GPU（16 GiB 显存起步），两套模型 22-23 GiB
- 视频是模板化解说（总结卡/贡献卡/结论卡），不是自由叙事
- 口播质量取决于 MegaTTS3，技术词仍需读音规则维护
