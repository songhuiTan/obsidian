# 万字长文：做了些爆款 Skills 以后，我对 Skills 的看法

作者：歸藏的 AI 工具箱

## 核心判断：Agent 在放大能力差距，而不是抹平

普通用户只知道「Agent 能写代码」「Agent 可以调 Skill」，头部用户已默认理解文档、规则、memory、loop、MCP、CLI、工具调用、权限、安全沙箱、上下文工程、定时任务、心跳、文件系统、代码执行和 Skill。

Agent 时代不是平权，是 K 型分化。

## Skill 的定义

> Skill 是把专家经验、工作流、品味和工具调用封装成可分发、可复用、可迭代的 Agent 能力单元。

它不是单纯的提示词，也不是传统意义上的 App。它是 Agent 时代的「能力商品」——用户不需要理解底层 MCP/CLI/memory/loop，只需要知道它解决什么问题、产出什么结果。

### Skill vs Prompt

Prompt 难以分发、没有版本管理、缺少安装调用语义。Skill 把提示词、规则、示例、工具调用、文件结构、脚本、依赖和使用说明打包，变成可安装、调用、迭代和传播的能力包。

## 好 Skill 的信息架构：中心短，辐射厚

**SKILL.md**：只放高信号流程和判断
**references/**：重文档和领域材料，按条件读取
**scripts/**：确定性逻辑，让 Agent 调用而不是重写
**assets/**：模板、schema、示例、字体、主题、版式骨架
**描述（description）**：不是广告，是路由触发器——描述用户什么时候需要它

## 好 Skill 的设计原则

- 把专业品味变成模型可执行的约束
- 把 AI 的任务从「自由设计」降级成「在高质量骨架里填充」
- Gotchas（失败案例库）是最高价值内容——比正向说明更能提升稳定性
- Every Skill is a tax——每一句都要问：没有这句 Agent 会不会做错？

## 设计类 Skill 的典型约束

- 不使用纯白纯黑
- 不让用户任意输入 hex，只提供验证过的主题色板
- 不用紫色多彩渐变、发光、大面积 blur
- 动画只用 transform 和 opacity
- 图文卡片优先真实摄影，AI 生图只是兜底
- 版式骨架先被人工验证，AI 负责组合和微调

## Thin Harness, Fat Skills

大的 harness 把工具定义、协议细节塞满上下文，带来更高延迟和更高 token 成本。
薄 harness 提供最小运行环境，Skill 按需加载。

## Skill 生命周期

1. 发现真实需求
2. 做一次高质量产物（先别抽象，先解决真实任务）
3. 抽象流程（识别可复用步骤、输入、输出、约束、工具）
4. 工程化模板（固化审美、版式、调用、验证和修复机制）
5. 跨模型测试（好模型看上限，差模型保下限）
6. 封装发布（GitHub + README + 示例 + 安装方式）
7. 内容分发（小红书/Twitter/公众号/视频展示结果）
8. 收集反馈

## Skill 生态建议

- 推荐 10 个精选 Skill 并讲清楚怎么用，远好过给几千个列表
- GitHub 做基础分发和跨平台覆盖，小红书做视觉案例分发
- 每个 Skill 页面需说明：解决的问题、适合场景、输入输出、典型提示词、截图/视频、谁用过、常见失败、安装方式

## Skill vs Gene

- **Skill**：人类预先沉淀的能力包，有创建者、边界、流程、版本
- **Gene/Capsule**：运行中从成功经验自动长出能力，带成功率、变异历史
- 长期方向：人的品味定边界，Agent 收集证据、提出改动、补充 eval

## 盗用防御

> 盗用不是靠藏，防御方式是持续分发

开源覆盖更多平台 → 用影响力威慑盗用者 → 做自媒体让用户知道源头 → 持续迭代建立领先 → 社区案例形成品牌资产

## Skill 的扩展边界

- **浏览器 Skill**：浏览器是大众最熟悉的工作环境，Skill 以「现成脚本/一键执行」的形式出现
- **硬件 Skill**：AI Desk Card 让 AI 接管物理环境 UI（安装固件、配置 Wi-Fi、墨水屏刷新）
- **游戏 Skill**：从玩法原型到素材采集、绿幕抠图、视频音乐、Electron 打包、GitHub Actions 全流程封装
