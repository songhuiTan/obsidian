# 开源「仓颉.Skill」3.0，你现在可以蒸馏任何视频（包含画面）

## 概述

仓颉.Skill（cangjie-skill）是袋鼠帝的开源项目——把手头的**书、长视频、播客**蒸馏成可直接装进 Agent 的 Skill 文件。

3.0 的核心突破只有一句话：**从"只抓声音"进化到"连画面一起看懂"**。

2.0 时代的致命短板是：软件教程、代码实操、商业拆解类视频，关键信息在**黑板的公式、PPT 的架构图、屏幕上的按钮排布**里，口播根本没念。只转写音频，蒸馏出来的 Skill 是残缺的。

> **归档日实测（2026-11-04）**：`kangarooking/cangjie-skill` **12,063 ⭐** / 1,420 fork / 23 open issues / **MIT** / Python / 2026-04-16 建库 · 最后 push 2026-10-02。
> 文中称"突破 12K Star"——**属实**。
> 姊妹仓 `kangarooking/kangarooking-skills` **696 ⭐** / 114 fork / **无 license** / 今日（11-04）仍在提交 —— video-downloader 就挂在这个 repo 的 `tree/main/video-downloader` 下。

## 一、引擎：LongCat-2.5 的"原生多模态"

美团新一代模型，**1.6 万亿总参 / 约 480 亿激活的 MoE**，全流程训练推理跑在国产 AI 芯片超节点集群上。文中标注"即将开源"（**归档日未核实开源状态**）。

两个升级点直接决定视频蒸馏能走多远：

### 1）原生多模态 ≠ 外挂视觉模型

作者给的比喻很准：传统方案像**"纯文字大脑鼻子上架了一副近视眼镜"**——先让视觉小模型把图翻译成文字转述，再喂给语言模型。中间隔了一层转述，**画面里的位置关系、代码缩进早就丢光了**。

LongCat-2.5 走原生路线（**RVQ 残差向量量化**）：图像在原分辨率下直接切碎成类汉字式的离散视觉 token，在底层语义空间里文字与图片平起平坐。看视频帧等于"自己睁眼盯屏幕"——代码、按钮排布、图标变化直接从原生像素读懂。

> 这是本文最有价值的技术判断：**转述层就是信息损失层**。任何"视觉模型→文字→LLM"的级联，都在编码阶段丢掉了空间结构。做多模态提取时，这一条决定了上限。

### 2）为长程任务而生的端到端工程能力

- **1M 上下文**：一口气塞进约一千页技术文档 / 一个完整项目代码
- **Trajectory2Task 机制**：抓出 Agent 此前干不好的任务轨迹，逆向分析"到底哪一步犯了蠢"，恢复失败现场后针对性做 RL —— 训的是"从搭建、跑依赖、报错排查到调通交付"的端到端能力
- **W4A4 量化**：国产算力平台上推理吞吐提升 **40%+**

## 二、仓颉.Skill 3.0 的底层重构

两个工具分工明确：

| 组件 | 职责 |
|------|------|
| **video-downloader** | 脏活累活：下载视频、抽语音、解析画面、整合带时间戳的原始信息 |
| **cangjie-skill** | 只做蒸馏：把复杂知识文本提炼、结构化，产出 Skill 文件 |

关键工程妥协：LongCat-2.5 的 API **只接受 URL 上传**，作者找了个可免费上传视频并返回临时公网地址的站点中转——"临时但也够了"。这是个脆弱环节，迁移时要替换。

### video-downloader 六大升级

1. **新增视觉理解**：语音转写之外，增加**关键帧 / 完整视频 / Agent 智能选段**三种模式，补充画面、屏幕文字、动作、剪辑信息
2. **Agent 方案优化**：先分析完整文案，再切重要片段交给 LongCat-2.5；**最长每 10 分钟切一段**，支持并发
3. **语音转写优化**：优先用平台字幕 → 其次免费的**硅基流动 SenseVoiceSmall** → 本地 Whisper 仅在用户明确选择后使用
4. **新增视频号支持**：可直接输入视频号链接，首次扫码登录后保存授权状态复用
5. **速度与稳定性**：默认下 1080p，增加**断点恢复和多级缓存**；失败只重跑出错片段，不重复下载整个视频
6. **输出 multimodal_transcript.md**：含口播、画面事实、屏幕文字、动作、时间戳——**交给仓颉时仓颉本身不需要改**

### cangjie-skill 侧的优化

- 响应反馈：**默认只蒸馏出一个 skill**，不再一次性产出多个（之前的问题是"产出太多不方便管理"）
- 9 月中旬刷新过安装底包，老用户需重新拉 Release

## 三、三个实测案例（这是全文最有价值的部分）

作者在 **Codex 环境**下以 LongCat-2.5 为底座，挂载两个工具跑完整流程。

### 案例 1：B 站 4.5 小时深度访谈（孙宇晨 × 邵艾伦）

- video-downloader 处理**半小时**（原视频 1G，光下载就占大半）
- 用 Cookie 直接打捞 B 站 AI 字幕，再用 LongCat-2.5 提取阶段性关键画面
- 仓颉蒸馏**约 50 分钟**，产出一套"孙学决策 Skill"
- 验证提问「孙宇晨提到的买房策略是什么」→ 给出流动性与资产配置逻辑，**并标明原视频哪一段、核心前提是什么**
- 追问「哪些领域在 AI 时代真正有前景」→ 拆出底层算力基建 / 垂直场景 Agent / 个人 IP 资产化三层，无套话

### 案例 2：视频号（薄肌理论 / 黄毛理论）

- 输入视频号链接 → 终端弹**微信扫码登录** → 几分钟扒下原视频
- LongCat-2.5 在这条链路里**既当 Codex 的底座模型把控流程，又当视觉模型分析画面**——"又当爹又当妈"
- 产出的「黄毛薄肌 Skill」答「为什么要练薄肌」时，除提取 13%–15% 黄金体脂率，还**主动补了一句**：这是男性参考标准，女性健康体脂应在 20% 左右，不可盲目照搬
- 这体现了**主动纠偏能力**：不只是搬运，会替原作者打补丁防误导

### 案例 3：YouTube 达利欧《经济机器是如何运行的》（1.4 亿播放）

- 难点在于**光听音频根本搞不懂**：全是动态天平、去杠杆三大工具、信贷周期齿轮
- video-downloader 把交易杠杆示意图、央行印钞与紧缩的图表关系精准切片注入文本
- 验证提问「经济运行框架的核心特征」→ 梳理交易驱动 / 短期债务周期 / 长期债务周期 / 通缩性去杠杆闭环，**并主动指出模型局限**：把经济抽象为机械齿轮，现实中低估了地缘政治与非理性心理冲击

## 成本实况（作者口径）

- LongCat-2.5 标价 **百万 token 3 毛**，3 亿 token 约 30 元
- 新老用户可领 **1000 万 token**，且命中缓存部分不计消耗
- 作者蒸馏以上超长视频，**合计仅消耗 755 万 token** —— 连赠送额度都没用完
- 对比：之前用其他模型，仅蒸馏文字内容每次打底 ~1000 万 token

> **成本口径需注意**：755 万 token 之所以这么低，很大一部分是缓存命中 + 平台字幕直接取用（省掉了 ASR token）。换模型或换平台后不具可比性。

## 关键洞察

1. **"转述层即损失层"是可迁移的判据**。原生多模态 vs 外挂视觉模型的差别，不只是准确率，而是**信息在编码阶段是否被降维**。做任何跨模态提取（截图转 markdown、图表转数据、UI 转代码）时，这条决定上限。
2. **视觉选段必须由 Agent 决策，不能均匀抽帧**。"每 10 分钟切一段 + 先分析完整文案再决定切哪里"这个设计，比固定间隔抽帧省得多也准得多——**均匀抽帧会漏掉讲解最长的那张架构图**。
3. **断点恢复 + 局部重跑是长任务的必需品**。几个小时的处理，任何一环失败都不能整锅重来。这条对任何长链路 Agent 都成立。
4. **蒸馏的价值边界作者自己划清了**："能拿到别人的知识框架，永远替代不了你自己的真实体验。"孙学蒸馏得再牛，商业判断还得自己试错；薄肌理论拆得再透，体脂率不会凭空下降。这句话比全文的营销部分诚实。
5. **默认只产出一个 skill 是对的**。之前产多个 skill 导致管理混乱——这与本库 372 篇归档的困境同构：**产出质量不取决于生成能力，取决于归档和检索纪律**。

## 战略分析

这篇对小谭不是"又一个开源项目"，而是**一条已经在跑的生产线的升级公告**——你本机已有 `~/projects/z-skills/` 下的 video-downloader。

### 与现有栈的对照

| 维度 | 仓颉 3.0 方案 | 小谭现状 | 差距判断 |
|------|-------------|---------|---------|
| 视频下载 | video-downloader（1080p/断点恢复/视频号支持） | 已有旧版 video-downloader | ⚠️ **需升级**：视频号支持 + 断点恢复是新增能力 |
| 语音转写 | 平台字幕 → 硅基流动 SenseVoiceSmall → Whisper | 取决于旧版配置 | ⚠️ 平台字幕优先策略能显著省 token 和时间 |
| 视觉理解 | LongCat-2.5 关键帧/整片/智能选段 | **完全缺失** | ❌ **这是最大缺口**——画面信息现在全丢 |
| 中间产物 | multimodal_transcript.md（口播+画面+屏幕文字+动作+时间戳） | 纯文本转写 | ❌ 缺结构化中间层 |
| 蒸馏出口 | cangjie-skill → 单个 Skill | 手工写归档 md | ⚠️ 手工 vs 自动，质量取决于人 |
| 成本 | 755 万 token / 三个长视频 | — | 参考价值高 |

### 具体该做的三件事（按性价比）

1. **升级 video-downloader，不动仓颉**。文章明确说仓颉侧不需要改——这是最省事的路径。升级点在：视频号支持、断点恢复、平台字幕优先、`multimodal_transcript.md` 输出格式。
2. **补视觉层，但不必绑 LongCat-2.5**。视觉理解的关键是"关键帧 + Agent 选段"的**流程**，不是特定模型。可以用现有多模态能力（如 vision 工具）跑同样的"先读全文案→再决定切哪段"逻辑，避免为单一模型绑死。LongCat-2.5 值得试的原因是好用且便宜，但它的 API 只收 URL 这一点是硬伤（作者自己也是靠临时中转站绕过的）。
3. **把这个流程接到知识库归档线**。目前 `kb-archive-article` 只处理图文；视频类归档（B站/YouTube/视频号）走的是另一条手工路径。仓颉 3.0 的 `multimodal_transcript.md` 正好是可以直接喂给归档流程的中间格式——**这能补上"视频类内容信息密度低于图文"的长期短板**。

### 该泼的冷水

- **`kangarooking-skills` 仓库无 license**。video-downloader 挂在那里，商用前必须确认授权；对比 cangjie-skill 是 MIT，这个差异要看见。
- **cangjie-skill 最后 push 是 2026-10-02**，距今一个月；文中说"9 月中旬刷新过安装底包"，**老用户必须重新拉 Release**，否则跑的是旧底包。
- **URL 中转站是单点**。临时公网地址随时失效，这条路不是稳定生产方案。
- **作者身份是推广方**（LongCat 免费额度活动），成本与效果数据带有立场。视频号扫码登录、B站 Cookie 打捞这类能力在不同账号状态下成功率差异大。
