## 概述

一篇 Dify 1.16 深度架构拆解（原文已有 9 张架构图）被用作完整测试素材。使用开源项目 **gimi-illustration** 重新配图——一个把"文章配图"做成 AI Agent Skill 的工具。输入文章，Skill 负责拆内容、定策略、组 prompt、调用生图、做 QA，并交付每张图的插入位置和设计理由。

最终产出 9 张 16:9 配图（1672×941px），全部使用同一套角色锚点、色彩纪律和叙事方式。测试围绕一个核心命题：**能不能让同一个个人 IP 持续参与复杂技术内容的表达，同时不把技术图变成一组可爱贴纸？**

## 核心框架：内容→视觉协议

项目最关键的设计不是在生图模型里，而是在它外面加了一层 **内容到视觉的协议**。工作链路：

**路由判断 → 内容分析 → 配图策略 → Prompt 组装 → 双参考生图 → QA → 结构化交付**

模型仍然负责画，但"画什么、为什么画、角色必须长什么样、失败了怎么判"由 Skill 约束。相当于给一个能力很强但容易自由发挥的插画师，补上了编辑、导演、角色设定师和质检员。

### 三层逻辑拆解

| 层级 | 阶段 | 核心动作 |
|------|------|----------|
| **第一层** | IP 录入（Step 0） | 先确认角色固定外形、不可丢失特征、参考图类型、双参考策略，生成标准风格校准图。**形象方案确认前禁止生图** |
| **第二层** | Shot Config 编译 | 两轴分析（结构轴：单点/对比/路径/状态/风险/隐喻_互补轴：图承担骨架与情绪，文字承担论证与细节）→ 六步提炼 → 结果写入 `shot-config.md`，不是只存在于一次对话 |
| **第三层** | Prompt 组装 | 13 段拼接顺序：参考图 → IP 描述 → 风格 DNA → 留白 → 风格适配 → IP 锁定 → 构图 → 核心信息 → 具体物件 → 标题与情绪 → 比例 → 标签 → 负向约束 |

### 关键设计细节

- **IP 描述放在风格之前**：先告诉模型"谁不能变"，再告诉它"怎么画"
- **角色色和场景色分层**：角色保持全色，场景以黑色抖动线稿为主，软蓝强调路径，软橙最多少量告警与编号。避免场景色污染角色服装
- **负向约束具体化**：不要 PPT 信息图、不要光滑矢量、不要渐变、不要大面积色块、不要彩色标签底、不要在原文无对应语义时默认塞放大镜和灯泡

## 双参考体系

| 参考类型 | 用途 | 锁定的维度 |
|----------|------|-----------|
| **角色设定图** | 锁定身份 | 发型、比例、服装、配饰（code2rich：巨大上扬尖刺黑发、Q 版大头短身、皇家蓝无袖背心、深蓝短裤与蓝白鞋、胸前带红白十字图形的椭圆吊坠） |
| **风格校准图** | 锁定表达 | 线稿风格、留白方式、场景色系、整体氛围——不是具体文章场景，而是"这个角色进入当前画风后应该怎么画" |

只传设定图，角色可能对了但线条和氛围会漂；只传风格图，画风可能对了但外形逐张变形。双参考在两个维度同时上护栏。

## 原图 vs 新图实测对比

| 对比组 | 原图特点 | 新图特点 | 本质差异 |
|--------|----------|----------|----------|
| **总览图** | 结构密度和术语精度，精确查边界 | 请求路径改写成空间旅程，角色带读 | 地图 vs 导览 |
| **数据平面** | 清晰区域说明四种存储 | 四种不同容器，角色站在中央分拣 | 文档 vs 隐喻 |
| **双沙箱** | 强调代码节点和 Agent Shell 进入不同运行时 | 短时计算胶囊与持续工作区左右并置，角色举盾 | 抽象边界 vs 可感知空间 |

核心结论：**原图更像地图，新图更像导览。** 关键边界保留精确图，重要判断增加 IP 化解释图——不是替代，而是互补。

## 个人 IP 的三层资产体系

| 层级 | 名称 | 内容 |
|------|------|------|
| 第一层 | **身份资产** | 发型、服装、配饰、比例和颜色 |
| 第二层 | **风格资产** | 线条、留白、点色、构图和标签纪律 |
| 第三层 | **叙事资产** | 角色如何指路、拆模块、检查风险、带读技术链 |

前两层让读者认出你，第三层让读者记住你是"怎么解释问题的"。当这三层被写进文件（而非只存在于某次 prompt 里），个人 IP 从一张图片变成一套可复用的内容系统。

长期飞轮：**文章沉淀观点 → Shot Config 沉淀视觉语法 → 校准图稳定角色 → 新内容强化读者记忆 → 个人 IP 反过来提高内容辨识度。**

## 关键洞察

- **不要神化。** 不是新生图模型，图像仍由平台 ImageGen 等生成；Shot Config 若误读原文，模型会把误读画得更生动
- **隐喻图与架构证据图的用途不同。** 对深度技术文章，最佳组合是：关键边界保留精确图 + 重要判断增加 IP 化解释图
- **授权边界。** 仓库 Skill 代码和工作流采用 MIT License，但自带的 Gimi 角色形象不属于 MIT 范围。做长期个人品牌要录入自己的 IP，而不是把别人的角色变成自己的品牌资产
- **个人 IP 的一致性 ≠ 每张图摆同一个姿势。** 真正的一致性是同一个人面对不同问题时，仍有稳定的身份、色彩和解释方式

## 战略分析

### 与现有工具链的对照

该项目解决的问题和「Visual IP Illustrations」同属"文章配图 AI Skill"品类，但路线截然不同：

| 维度 | gimi-illustration | visual-ip-illustrations |
|------|-------------------|------------------------|
| 定位 | 个人 IP 视觉系统构建器 | 多角色文章配图 Skill |
| 核心创新 | Shot Config 策略文件 + 双参考体系 | 多角色路由 (7个 IP) + QA gate |
| IP 录入 | 完整 Step 0（身份冻结 + 校准图 + 双参考） | 无专门录入环节，角色预定义 |
| Prompt 组装 | 13 段可组合模板 | 单次 prompt 生成 |
| 输出审核 | 内置 QA 环节 | QA gate 检查输出质量 |
| 文件化程度 | shot-config.md 作为持久化策略 | 无持久化策略文件 |
| 风格锁 | 双参考（身份 + 风格两层） | 单层角色风格描述 |

gimi-illustration 在"视觉记忆系统化"这条路上走得更深——它不是每次从头写 prompt，而是用 `shot-config.md` 沉淀策略，用双参考固定表达。这使得长期内容创作可以实现"风格复利"，而非每次从头对齐。

### 与 Hermes 生态的整合潜力

本项目对当前 Hermes 知识库的直接影响有限（它是生图领域，Hermes 是 Agent 框架），但有两点值得关注：

1. **Shot Config 的启发**：`shot-config.md` 模式可以推广到 Hermes Skill 的开发——不只在 prompt 层面约束 Agent 行为，而是用可提交到版本库的配置文件来沉淀 Agent 的"表达策略"。对应到 Hermes Skill 体系，这类似于在 SKILL.md 之外增加一个 express-config.md 做风格与质量约束。

2. **IP 录入 → 校准图 → 双参考的流程设计**：这个"先冻结身份再允许产出"的流程，对 Agent 工具的使用也有借鉴——先完成上下文和约束的注册（类似 TencentDB Memory 的 L0-L3 分层），再允许 Agent 产出。先有协议，后有行动。

3. **与现有配图工具的关系**：当前知识库已有 OpenClaw 公众号配图自动化（2026-03-18）、Visual IP Illustrations 以及 fireworks-tech-graph 架构图工具。gimi-illustration 填补了"个人 IP 长期一致性"这个空白——它是做品牌资产的，不是做一次性配图的。
