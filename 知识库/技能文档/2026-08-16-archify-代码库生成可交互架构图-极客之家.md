## 概述

接手不熟悉的代码库，最花时间的不是改代码，而是先搞明白整体结构——哪个模块负责什么、请求从哪进来、数据落到哪。文档通常不写，写了也多半过时，只能自己翻代码拼。

**archify**（GitHub 1.3 万+ Star）：一个 Agent Skill，装到 AI 编程工具上（Cursor、Claude Code、Codex CLI、OpenCode），让 AI 直接读代码仓库，读完生成**可交互架构图**，输出 HTML 文件，浏览器打开就能看，发给同事不用装任何东西。

README 金句：**"这些图是从真实仓库里读出来的，不是只靠提示词画出来的。"**

## 具体能做什么

### 1. 直接读代码仓库，不靠写一大段描述

- 大部分 AI 画图工具：你先用文字描述系统，它照描述画——描述决定图对不对，等于画图前你得先自己搞明白架构，本末倒置
- archify 自己读仓库：入口在哪、路由怎么分发、模块之间谁调谁，都是从代码里翻出来的
- 你只要说一句"梳理这个仓库的运行时架构"

### 2. 图上的节点能跳回源码

- 节点带 **SRC 标记**，点开直接跳到对应文件和行号
- 位置经 **Git 校验，固定在具体 commit 上**，不会今天这个明天变那个
- 图上画的与代码真实存在对得上，不是 AI 看着目录猜的

### 3. 五种图，从不同角度看一个系统

| 图类型 | 用途 |
|--------|------|
| **架构图** | 组件、服务、数据库、云资源、安全边界，系统整体结构 |
| **工作流** | 泳道式流程图，适合 CI/CD、审批流、异常分支 |
| **时序图** | API 调用链、缓存回源、鉴权检查，谁调谁/什么顺序/返回什么 |
| **数据流图** | 数据从哪来/经过哪些处理/存到哪去，敏感数据边界可标注 |
| **生命周期图** | 状态机、重试、等待、终态，如订单从创建到完结 |

### 4. 生成的是能交互的图，不是死图片

- 按 `/` 搜索节点；点组件看上下游；按 `R` 探查两节点间完整路径
- 播放**引导故事**：像幻灯片一章一章讲系统
- 按 `F` 进演示模式（投屏自适应）
- **交互全部基于图里真实存在的节点和连线，不编造不存在的调用关系**

### 5. 出图质量不靠运气

- 换分工：**模型只产出结构化 JSON**（节点+连线），布局和画图交给专门渲染程序
- 画完有自动检查，不通过不交付；失败时告诉你具体哪出问题（哪个标签和连线打架），建议怎么修
- 输出质量稳定，不会这次能用下次翻车

### 6. 导出和分享是认真做的

- 深浅两套主题一键切换
- PNG 按 **4 倍分辨率**渲染（PPT/打印不糊）
- SVG 一份文件同时嵌深色+浅色两套样式——放 GitHub README 自动跟随读者系统主题
- 导出 WebM 动态图 + 1200×630 标准分享卡片（release note/发动态直接用）

### 7. 改架构可以先对比再合并

- 改动前后两份图对比，生成 **Before / Delta / After 三个视图**
- 新增/删除组件、改动连线逐条列出，评审比口头描述清楚

## 上手

```bash
# 直接运行
npx skills add tt-a1i/archify -g

# 试一下不长期装
npx skills use tt-a1i/archify@archify --agent codex
```

装完在项目里说：「使用 archify 梳理这个仓库的运行时架构。」调整也用大白话：「加一个 Redis 进去」「把鉴权模块挪到左边」「把回滚路径标出来」——**只改提到的部分，不推倒重画**。

## 作者看法

- **方向选得好**：架构图最怕和代码脱节——凭文字描述画的图，画完那一刻可能已经不准（描述的是你脑子里的系统，不一定是代码里真实的系统）。让 AI 读代码、节点能跳回源码核对，图就成了**一份能核对的文档**，而不是凭印象画的示意图
- **分工处理得好**：理解需求/组织信息交给模型（AI 擅长）；布局/渲染/检查交给程序（要求稳定）——拆开后出图质量下限远高于 AI 直接写 SVG
- **边界清楚**：不是绘图编辑器（不能拖拽改图），不做 Mermaid 转换，只管"把代码库变成能拿出去讲的图"这一段

| 视角 | 深度使用体验 | 工具介绍 |

**核心启发：**

1. **"模型产出 JSON、程序负责渲染"的分工是 archify 出图稳定的关键**——理解/组织交给 LLM（擅长），布局/渲染/检查交给确定性程序（要求稳定）。这与 Semantica 的"确定性运行"、gbrain 的"零 LLM 成本图谱"是同一设计哲学：**LLM 负责模糊的部分，确定性代码负责精确的部分**。

2. **"节点 SRC 标记 + Git commit 校验"把架构图变成可核对文档**——解决了架构图最致命的"与代码脱节"问题。这与此前归档的"代码图谱"系列（sense/codegraph/CodeGraph）同主线：代码理解前置成可查询资产。

3. **"只改提到的部分，不推倒重画"是 Agent 工具交互的良好实践**——增量修改而非全量重生成，与用户"新建独立 skill 不改已有"的偏好精神一致。

4. **对用户的实用价值**：archify 支持 Codex CLI（`--agent codex`），且知识库已有归档但无安装记录——如果用户常接手新项目或讲系统架构，值得装一个（`npx skills add tt-a1i/archify -g` 一条命令）。

**一句话**：archify = 读代码库生成可交互架构图的 Agent Skill，"模型产出 JSON + 程序渲染检查"的分工和"节点可跳回源码、Git 校验固定 commit"的可核对性是核心价值；本归档与已有 Archify 归档形成两篇互补评测。
