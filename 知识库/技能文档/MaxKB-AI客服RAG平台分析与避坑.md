# 为什么你的AI客服总答非所问？

> MaxKB 开源平台分析：自动文本切分、RAG pipeline、agentic workflow 引擎 + MCP tool-use、零代码集成。但零代码不等于零维护。

---

## 一、自动文本切分——省下的开发时间和埋下的检索噪声

RAG pipeline 的核心：文档 → 拆块 → 向量化 → 存库 → 检索 → 生成答案。

MaxKB 把拆块过程自动化了，用户上传 PDF/Word 或填网页链接，它自己跑切分、向量化、存库。

**技术上：**
- 切分通常有固定长度 + overlap，或让模型判断语义边界两种思路
- 切完后用 embedding 模型转成向量
- 用户提问时，问题向量化 → 找最接近的块 → 拼上下文 → LLM 生成答案

**风险点：** 参数（chunk size、overlap）被收进平台默认逻辑。合同（结构化文本）和产品说明（半结构化）可能需要不同的切分策略，自动切分不一定开箱即用，需要测几轮才稳。

> 企业知识库项目最常见的失败原因，往往不是模型选错，而是 **ingestion 这头没处理干净。**

---

## 二、Agentic Workflow 引擎 + MCP Tool-use

纯问答 AI 只能被动接问题。企业想要的是：客户说「我要退货」，AI 先查订单状态 → 符合条件就调用退款接口 → 或转给人工并附上上下文。

MaxKB 的 workflow 引擎带 function library 和 MCP tool-use 能力：
- 定义一系列节点，让 AI 按业务规则一步步推进
- 模型无关（DeepSeek/Llama/Qwen 私有模型 + OpenAI/Claude 公有模型）
- MCP tool-use 让 agent 更可靠地调用工具或插件

**隐藏成本：** 后期维护和权限细节——谁能调用哪个工具、调用结果怎么审计、失败了怎么回滚，这些在纯聊天阶段不会暴露，一旦 workflow 跑起来就全冒出来了。

---

## 三、零代码集成——省的是开发，不省治理

零代码集成指通过 API、embed 代码片段或 webhook，把问答能力塞进现有页面或流程。

**确实省了：**
- 自己搭 RAG 链路、维护向量库、处理 embedding 更新
- 模型可按需换（想省钱上本地 Qwen，想效果切 Claude）
- 数据留在自己服务器

**不省的：**
- 权限控制、数据隔离、审计日志等企业级要求
- 「AI 回答了不该让某部门看到的内容」或「工具调用权限越权」
- 业务系统怎么安全调用、怎么记录每一次决策依据

> 零代码只是把接口暴露出来，治理问题依然要集成方自己负责。

---

## 四、验证 MaxKB 是否适合——三步测试法

**Step 1：小知识库测试**
- 只放 2-3 类文档，观察自动切分后的 chunk 质量和检索召回率
- 同一个问题，不同切分策略下答案准确度和来源引用是否稳定

**Step 2：带 workflow 的简单场景**
- 例如「查订单 + 判断退款资格 + 生成工单」
- 看 MCP tool-use 在实际调用外部接口时，是否能按预期顺序执行、失败时是否给出清晰错误信息

**Step 3：零代码集成模拟**
- 用 API 或 widget 嵌入一个测试页面
- 检查返回结果是否包含来源 chunk、是否方便在业务系统里做权限过滤

> 真正决定成败的，从来不是平台宣称了多少能力，而是**你自己的文档质量、切分策略和权限模型配得怎么样。**
