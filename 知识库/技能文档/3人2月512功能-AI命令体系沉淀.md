---

## 两条工程主线

**Harness 自治**：人只定规则，把执行全权交给 AI。人不在审查的每一轮里，只看最终报告。命令不是"让 AI 做事"，是"给 AI 套上纪律边界，让它在边界内自治"。

**Loop Engineering**：把审查、修复、验证都做成自动循环，直到收敛（零问题）才退出。能循环的就不让人介入，把串行等待彻底消掉。

## 一、需求与方案族

| 命令 | 用途 |
|------|------|
| `/prd` | 按功能复杂度选章节组合写需求文档，含产品价值/成功指标/用户画像/优先级 |
| `/10-bs` | 并行十视角审视同一命题（业务闭环/技术边界/多租户/安全/性能），只综合结论落盘 |
| `/plan-template` | 旗舰方案模板——先讨论稿再定稿，禁止分期交付同一方案，§9 实现任务派发并行 backend/frontend/operation 三个子 agent 产文件映射+API 契约+DDL+组件接口 |

`/plan-template` 关键设计：
- 第一轮只产出讨论稿——范围/待确认问题/风险/不做项清单，每个待确认问题带 AI 推荐
- 禁止分期交付同一方案（出现"第一期/第二期"直接判违规）
- 定稿时并行派发子 agent 搜索代码库，主 agent 合并去重+一致性校验

## 三、审查族（Loop Engineering 旗舰）

### `/kd-review`：全自动审查循环，直到零问题收敛

**第一阶段，并行审查**：变更拆 21 个窄范围 bucket（后端按服务、前端按页面、横切按关注点），每个 agent 只审 1-5 文件，各自独立 worktree，全部同时启动。

**第二阶段，streaming 修复**：不等全部审查完成。每个审查 agent 一返回结果，立刻派修复 agent，🔴 阻断问题直接修，不询问不等确认。墙钟时间 ≈ `max(审查) + max(修复)`，非相加。

**第三阶段，收敛循环**：连续 3 轮零任何问题（🔴🟡🔵 全清）才退出。每轮增量审查——只重审上轮有问题 bucket，连续两轮零问题的文件直接跳过。每 5 轮强制全量一次防盲区。

**提交前四道硬门禁**：
1. 编译
2. 单测+覆盖率（行 95%/分支 85%）
3. API 契约检查（跨仓 diff 防"前端调了后端不存在的端点"）
4. P0 E2E

任一失败自动派修复循环，最多 3 轮，全绿才提交。E2E 不可用时禁止自动跳过、禁止写 `expect(true).toBe(true)` 占位测试。

## 核心认知

研发的护城河已经从"我会做什么"挪到了"我沉淀了什么命令体系"。前者 AI 正在接管，后者才是把小团队产能拉满的关键。

遇到任何重复操作、依赖纪律的环节，第一反应不是"我来盯"，而是**"这能不能做成 harness + loop"**——给它套上纪律边界让它自治，给它一个收敛条件让它循环。
